# Распространение конфигурации nginx

Контроллер хранит шаблон конфигурации и каталог чувствительных файлов. Разослать поколение на
флот — операция `send`. На каждой ноде агент (не модуль) забирает объекты, собирает дерево,
делает `nginx -t` и `reload`. Модуль в этом контуре не участвует: он не ходит в store и не шлёт
`SIGHUP` мастеру.

Это не поставщик данных локального слоя. Списки адресов едут своим потоком JetStream в shm без
reload, см. [inspectors.md](inspectors.md#поставщик-данных). Здесь — файлы, из которых nginx
собирает рабочий конфиг, и перечитывание процесса.

## Что секретно, а что нет

Текст шаблона не секрет: имена vhost, директивы WAF, наборы инспекторов. Его контроллер видит,
хранит и хеширует. В шаблон не вставляют PEM и пароли — только ссылки `store:<uuid>`. Редактор
отбраковывает блоки `BEGIN PRIVATE KEY` и `BEGIN RSA PRIVATE KEY` при сохранении.

Содержимое объектов store секретно. Его шифрует браузер оператора на публичный ключ контура.
Контроллер видит ciphertext и кладёт его в Postgres (`store_objects.blob`). Приватный ключ — в
окружении агента (Secret Kubernetes, Docker secret, файл из env), на контроллер не попадает.

Один ключ на контур. Новая нода монтирует тот же Secret. Staging и prod не делят ключ.
Компрометация одной ноды раскрывает все объекты этого контура — цена схемы, без которой 101-й
узел не открыл бы старые UUID.

## Ссылка `store:<uuid>`

Синтаксис шаблона контроллера, не переменная nginx. Префикс `store:` и UUID RFC 4122, без `$` и
без фигурных скобок: иначе ссылка совпадает с `${...}` nginx и с `envsubst`.

```nginx
ssl_certificate      store:3f2a9c1e-4b2a-41c0-8f3a-000000000017;
ssl_certificate_key  store:9b1c70aa-0e11-4d2c-9c01-000000000018;
```

До `nginx -t` агент заменяет каждый токен на абсолютный путь к расшифрованному файлу, например
`/var/lib/waf/store/3f2a9c1e-4b2a-41c0-8f3a-000000000017`, режим `0600`. Мастер nginx видит
обычный путь. Если агент ссылку пропустит, `-t` упадёт на несуществующем относительном пути —
это отказ, не «unknown variable».

Один объект — один файл. Нода сама вычитывает UUID из шаблона, отдельный «список файлов для этой
ноды» не нужен. Подстановка содержимого внутрь директивы (литерал секрета в `nginx.conf`) не
поддерживается: бэкапы, `nginx -T`, error log.

## Объект store

Идентификатор — UUID, не хеш содержимого. Замена файла даёт новый UUID и правку ссылки; старый
объект не перетирается, откат — старый шаблон со старыми UUID.

Тело — ciphertext в Postgres, таблица `store_objects`: `id`, `type`, `metadata`, `blob`. Это не
хранилище тел запроса и не S3. Объекты мелкие (PEM, страница отказа); агент забирает их у
контроллера по uuid тем же контуром, что и поколение. GeoIP и прочие десятки мегабайт сюда не
кладут — [ниже](#что-сюда-не-кладут).

| Поле | Что это |
| --- | --- |
| `id` | Глобальный UUID, он же `store:<uuid>` в шаблоне |
| `type` | Зачем объект: `certificate`, `private_key`, `chain`, `ca`, `creds`, `dhparam`, `deny_page`, `other` |
| `metadata` | То, что можно показать без ключа: имя, заметка, срок |
| `blob` | Непрозрачный конверт (DEK + ciphertext), контроллер не открывает |

Шифрование — в браузере, гибридное: случайный DEK, AES-256-GCM на файл, DEK обёрнут публичным
ключом контура (RSA-OAEP SHA-256 или HPKE). Upload ciphertext идёт
`POST /api/<scope_uuid>/store`, не в бакет.
Целостность тела — AEAD и ключ контура. Подмена blob без ключа даёт ошибку decrypt на ноде, не
чужой PEM. Ряд в базе не обновляется: замена — новый UUID.

### Формат `blob`

Байтовый layout конверта, единый для всех держателей приватного ключа контура (агент, будущий
[crypto-сервис](https://github.com/exemt/placitum-crypto/blob/develop/docs/spec.md)):

```
байт      0      версия конверта, 0x01
байты   1..2      длина обёрнутого DEK, big-endian uint16
байты   3..N      DEK, обёрнутый RSA-OAEP-SHA256 публичным ключом контура
байты  N..N+12     nonce AES-256-GCM, 12 байт
байты  N+12..     ciphertext AES-256-GCM (включая 16-байтный tag на конце)
```

Явная длина обёрнутого DEK — чтобы формат не завязывался на размер ключа контура: сейчас RSA-4096
даёт постоянные 512 байт, но ротация на другой размер не должна менять код разбора, только число в
заголовке. Версия — чтобы будущая схема (HPKE) не читалась старым разбором как RSA-OAEP.

## Поколение и `send`

Сохранить черновик ≠ разослать. `send` компилирует дерево пространства, проверяет, что каждый
`store:<uuid>` зарегистрирован, кладёт тела в Redis по `sha256` и пишет указатель в JetStream
KV `WAF_DESIRED/policy/nginx-pack`.

В KV едут только хеши: шаблон целиком в `max_payload` не закладывается, и лимит кадра горячего
пути ради него не поднимают (см. [body-storage.md](body-storage.md#inline)). Тела — шаблон,
шифротексты store и страницы отказа — лежат во внутреннем Redis контура под ключом
`waf.blob.<hex>` (`CONTROLLER_REDIS_INTERNAL_URL`, не обменник тел); одинаковое тело хранится
один раз, повторный `send` без правок только обновляет срок. Срок у блоба 300 с: опубликованному
поколению его продлевает keep-alive контроллера раз в минуту и возвращает пропавшие тела из
плана, старые поколения сгорают сами; нода, промахнувшаяся мимо истёкшего блоба, повторяет забор
раз в 30 с (см. [deploy/README.md](deploy/README.md#redis)).

```json
{
  "v": 1,
  "kind": "nginx-pack",
  "rev": 43,
  "sha256": "sha256:8f3c…",
  "prefix": "waf.blob.",
  "config": "sha256:df03…",
  "store": {
    "3f2a9c1e-4b2a-41c0-8f3a-000000000017": { "hash": "sha256:ce16…", "type": "certificate" }
  },
  "pages": { "blocked.html": "sha256:5b65…" }
}
```

`sha256` указателя — хеш дерева: он сводит хеш текста шаблона, пары «uuid → хеш шифротекста» и
пары «имя страницы → хеш тела». Правка любой части меняет его, поэтому именно он и сравнивается
с heartbeat. Секреты в открытом виде в хеш не входят — иначе контроллер не повторил бы значение
ноды.

## Что делает нода

Агент на хосте nginx, отдельный процесс (Go). Ключ — из окружения (`WAF_NODE_KEY` или файл Secret).
Перечень функций и границы — [nginx/agent/README.md](nginx/agent/README.md).

1. Watch KV, распаковать поколение.
2. Посчитать `config_hash` по полю `config` как есть — это то, что уйдёт в heartbeat.
3. Собрать UUID из токенов `store:<uuid>`, сверить со списком манифеста.
4. Забрать ciphertext `GET /api/<scope_uuid>/store/<uuid>/blob`, открыть ключом контура.
5. Собрать новое дерево: шаблон с путями вместо токенов, секреты `0600` и страницы отказа
   `0644` (см. [deny-pages.md](deny-pages.md#дистрибуция)).
6. `nginx -t` на новом дереве. Провал — боевое дерево не трогать, статус `apply_failed`,
   heartbeat со **старым** hash.
7. Подмена include, `nginx -s reload`.
8. Heartbeat: `config_hash` шага 2 и `conf_fingerprint` — md5 боевого файла, который лёг на
   ноду шагом 7. Второй нужен потому, что воркер в своём присутствии несёт отпечаток файла, а не
   поколения: сравнивать его с `config_hash` значит сравнивать md5 с sha256.

Агент, стоящий сайдкаром (аудит, архив, пульс — но не конфигурация), шагов 3–7 не делает:
у него нет ни бинаря nginx, ни его дерева. Роль задаётся явно (`nginx { manage off }` в
конфиге агента или `WAF_NGINX_MANAGE=off`), иначе такая нода вечно репортила бы
`apply_failed` при исправном всём остальном.

Поведение reload для модуля — в [deployment.md](deployment.md#перезагрузка-конфигурации): старые
и новые воркеры сосуществуют, инбокс с nonce, дренаж вердиктов. Агент этого не дублирует.

Размер `waf_shm_zone` в шаблоне можно написать; применить его `reload` нельзя. Агент не отмечает
узел `migrated` после `-s reload`, если поколение требует полного restart.

## Сходимость флота

Не по факту `send`. Desired — `config_hash` в KV. Actual — heartbeat агента по шаблону до замен.

```text
WAF_STATUS / node/<node_id>/<nonce>     heartbeat поколения, TTL
WAF_STATUS / node/<node_id>/agent       последняя попытка apply
```

Узел переехал, когда агент отчитался desired hash, а все живые воркеры `node_id` несут
`conf_fingerprint` этого агента. Пока жив старый `nonce` со старым отпечатком — на узле ещё
старый трафик, это дренаж, не откат. Флот переехал, когда это верно для инвентаря. Молчание за
TTL — дыра, не успех.

| Состояние | Смысл |
| --- | --- |
| `drift` | desired новый, actual старый |
| `apply_failed` | шаблон доехал, `-t` или decrypt нет; hash не обновлён |
| `migrated` | агент на desired `config_hash`, все живые воркеры — на его `conf_fingerprint` |
| `undecryptable` | ключ в окружении не открывает конверт (не тот Secret) |

Откат — `send` предыдущего шаблона. UUID на месте, повторно загружать файлы не нужно.

## API контроллера

Форма URI — обязательное требование: [requirements.md](requirements.md).
Пространство всегда в пути, не в query и не в теле.

| Метод | Назначение |
| --- | --- |
| `GET /api/<scope_uuid>/crypto` | Публичный ключ контура и fingerprint |

Ответ `GET /crypto` — публичная половина, приватной нет:

```json
{
  "alg": "RSA-OAEP-256",
  "public_key": "-----BEGIN PUBLIC KEY-----\n…",
  "fingerprint": "sha256:e0091916…"
}
```

Нет ключа в выкладке — `503 { "error": "crypto_unavailable" }`.
| `POST /api/<scope_uuid>/store` | Принять ciphertext, выдать UUID; тела в ответе нет |
| `GET /api/<scope_uuid>/store` | Каталог: uuid, type, metadata, size — без blob |
| `GET /api/<scope_uuid>/store/<uuid>` | Метаданные и blob (base64) |
| `GET /api/<scope_uuid>/store/<uuid>/meta` | Только метаданные |
| `GET /api/<scope_uuid>/store/<uuid>/blob` | Сырой ciphertext, для агента |
| `GET /api/<scope_uuid>/config` | Черновик шаблона |
| `PUT /api/<scope_uuid>/config` | Сохранить черновик, не публикуя |
| `POST /api/<scope_uuid>/config/send` | Упаковать, посчитать hash, опубликовать манифест |
| `GET /api/<scope_uuid>/rules/desired` | Поколение правил инспектора, см. [inspector-config-distribution.md](inspector-config-distribution.md) |
| `POST /api/<scope_uuid>/rules/send` | Собрать профили пространства и записать KV |
| `GET /api/<scope_uuid>/agent` | Черновик настроек агента и его хеш |
| `PUT /api/<scope_uuid>/agent` | Сохранить черновик, не публикуя |
| `POST /api/<scope_uuid>/agent/send` | Опубликовать `policy/agent-conf`; хеш прежний — ревизия не растёт |
| `GET /api/<scope_uuid>/agent/desired` | Ревизия и хеш, стоящие на флоте |
| `GET /api/<scope_uuid>/certificates` | Каталог сертификатов: имя, SAN, срок, fingerprint — без ciphertext |
| `POST /api/<scope_uuid>/certificates` | Привязать загруженные store-объекты (`cert_store_id`, `key_store_id`, опционально `chain_store_id`) к сертификату; метаданные не от браузера, а от crypto-сервиса, см. [crypto-service.md](https://github.com/exemt/placitum-crypto/blob/develop/docs/spec.md) |
| `DELETE /api/<scope_uuid>/certificates/<uuid>` | Удалить запись сертификата; `409`, если он привязан к серверу |

Превью секрета из контроллера нет. В каталоге — UUID и имя, которое оператор сам набрал.

## Настройки агента

Второй документ того же канала: KV `policy/agent-conf`, тема `waf.desired.agent`.
Блобов у него нет — он мелкий и не секретный, поэтому лежит в значении ключа
целиком: адрес архива, регион, имена бакетов и темп выгрузки
(`workers`, `queue`, `timeout`, корзины по видам объектов).

Это не поколение nginx. Здесь нет ни `nginx -t`, ни reload: агент заменяет пул
архивации на лету (`internal/retain/switch.go`), отставляя старый дописывать
свою очередь, — трафик при раскатке не участвует вовсе. Ревизии двух документов
независимы, и в кадре присутствия они лежат порознь: `config_hash`/`rev` — про
шаблон nginx, `agent_conf` — про эту настройку.

Документ **накладывается** на то, что дала нода файлом и окружением, а не
заменяет его. Названного в нём нет — работает нодино значение. Поэтому пустой
документ ничего не гасит: «контроллер про это молчит» и «выключи архив» —
разные вещи, и первое не должно делать второе на всём флоте разом.

Что этим каналом не приезжает и приехать не может:

- **Бутстрап агента** — адрес шины, контроллер, scope, ключ ноды, сокет
  вердиктов, каталог данных. Ими агент дотягивается до самой шины; доставить
  их шиной нельзя по кругу зависимостей.
- **Реквизиты S3** — секрет ноды (`WAF_RETAIN_S3_CREDENTIALS_FILE`). Граница
  та же, что у приватного ключа контура: контроллер называет хранилище, но не
  открывает его. Поэтому и проверка «эндпоинт есть — бакет обязан быть» стоит
  в контроллере, а «эндпоинт есть — реквизитов нет» ловится только на ноде:
  настройка не применяется, прежняя остаётся в силе, и нода говорит об этом
  `agent_conf.apply=apply_failed`.
- **Свойства ноды и образа** — бинарь nginx, каталоги конфига и обменника,
  `WAF_NGINX_MANAGE`. Они различаются у нод одного контура (раскатку применяет
  одна, архив ведут все), а документ здесь один на контур.

## Что сюда не кладут

- Наборы `waf_local_dataset` — состав в Postgres (`dataset_addresses`), на модуль
  едет снапшотом JetStream, см. [inspectors.md](inspectors.md#поставщик-данных).
  В `store_objects` списки не кладут.
- Страницы отказа — не секрет: едут секцией `pages` того же поколения, открытым текстом и
  по имени файла, см. [deny-pages.md](deny-pages.md#дистрибуция). Шифровать то, что и так
  уезжает клиенту, значило бы лишь спрятать её от каталога контроллера.
- CRS инспектора — образ сервиса. Локальные профили (`rule_files` / `rule_sets`)
  едут своим `send` в тот же бакет KV, см.
  [inspector-config-distribution.md](inspector-config-distribution.md).
- Бинарь модуля — пакет дистрибутива.
- Приватный ключ контура — только Secret/env агента.
- GeoIP и прочие справочники на десятки мегабайт — другой канал.

Разбор отвергнутых упаковок (один tar в NATS, JSON с PEM в KV, `$` в ссылке, хеш содержимого в
идентификаторе) — в [research/controller-config-distribution.md](research/controller-config-distribution.md).
