# waf_audit_sample

Доля разрешённых запросов, попадающих в аудит, в процентах.

```
waf_audit_sample <0..100>;
```

Контекст: `http`, `server`, `location`, наследуемая.
Умолчание: `100` — пишутся все запросы.

Прореживается только то, что нечем объяснить. Независимо от значения пишутся:

| Что | Почему |
| --- | --- |
| Отказ и редирект | Расследование начинается с них; сэмпл, умеющий потерять блокировку, — не сэмпл, а дыра |
| Волна, сорванная политикой (`waf_exception`: классы `timeout`, `absent`, `bus`) | Это отказ инфраструктуры, и по одному проценту таких записей его не увидеть |
| Молчание спрошенного инспектора | То же самое, но видное поимённо: из записи известно, кого не дождались |
| Запрос, отдавший объекты в архив | Непустая секция `store.archive` означает, что объекты переданы агенту, и он их перекладывает и чистит обменник. Выброшенная запись оставила бы их лежать до истечения TTL: сэмпл менял бы не объём журнала, а занятость обменника |

То есть значение действует ровно на «запрос прошёл, сказать больше нечего».

Любой спрошенный инспектор может сказать своё глаголом `audit` канала
действий: `set: on` — писать вопреки сэмплу,
`set: off` — считать, что жребий не выпал. Второе не сильнее сэмпла: всё из
таблицы выше пишется всё равно
([inspector-actions.md](../../inspector-actions.md#запись-и-архив)).

## Решение одно на запрос

У одного `ray` записей бывает две: отложенная запись фазы запроса и запись
фазы ответа. Решение принимается один раз и применяется к обеим — запись фазы
ответа без своего якоря не объясняет, что за запрос это был.

По той же причине решение смотрит на исход **всего** запроса, а не текущей
фазы: отказ на фазе ответа сохраняет и запись фазы запроса.

## Выбор равномерен по запросам

Жребий бросается на запросе, а не выводится из `ray`. Хеш от `ray` дал бы
устойчивое разбиение, при котором один и тот же клиент никогда не попадает в
журнал, — а это ровно тот клиент, которого потом ищут.

## Зачем

Запись — от восьмисот байт до полутора килобайт. При десяти тысячах запросов
в секунду это порядка десяти мегабайт в секунду и около восьмисот гигабайт в
сутки до сжатия ([audit.md](../../audit.md#сайзинг-аудита)); дальше по
конвейеру это шина, JetStream, вставка в ClickHouse и диск под ним.

Сэмпл — единственный рычаг, который убирает нагрузку со всех четырёх сразу.
Батчинг ([audit.md](../../audit.md#пачка)) снимает стоимость **сообщений**, но
не стоимость **строк**.

## Примеры

```nginx
http {
    # Контур целиком: пять процентов разрешённого плюс всё интересное.
    waf_audit_sample 5;

    server {
        listen 443 ssl;
        waf on;

        location / {
            return 204;
        }

        # Отладочный маршрут пишется целиком, пока идёт разбор инцидента.
        location /debug/ {
            waf_audit_sample 100;
        }

        # Проверка живости: разрешённые запросы не нужны никому, отказы нужны.
        location /health {
            waf_audit_sample 0;
        }
    }
}
```

## Ошибки конфигурации

| Ситуация | Реакция |
| --- | --- |
| Значение вне `0..100` | `nginx -t`: проценты, а не множитель |
| Не число | `nginx -t` |
| Две директивы на одном уровне | `nginx -t`: молчаливый выбор последней прятал бы опечатку |

Проверки — [nginx/tests/unit/audit-sample-\*.conf](../../../nginx/tests/unit).
