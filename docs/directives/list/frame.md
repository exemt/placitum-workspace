# кадры: механика протокола

Политика фазы кадров пишется общими семьями — фаза первым словом,
направление в том же слове: [inspect.md](inspect.md),
[deadline.md](deadline.md), [hold.md](hold.md),
[capture.md](capture.md), [verdict.md](verdict.md),
[body_limit.md](body_limit.md).

Здесь — то, что не обобщается: RFC 6455 и кадрирование gRPC.

```
waf_require_upgrade on|off [response=<name>];
waf_ws_strip_extensions <name> [<name>...] | all | off;
waf_frame_reassemble on|off;
waf_frame_control_rate <rate>|off;
waf_frame_cache frame|frame:c2s|frame:s2c ttl=<time> | off;
waf_frame_sample <fraction>;
```

Контекст: `http`, `server`, `location`, наследуемая.

Рукопожатие — обычный запрос: адрес, `Origin`, путь, авторизация,
капча идут фазой `request` и работают уже сегодня. Фаза кадров
начинается после `101`.

```nginx
location /ws/ {
    waf_ws_strip_extensions permessage-deflate;

    waf_frame_reassemble on;
    waf_body_limit  frame 256k block;      # потолок собранного сообщения
    waf_frame_control_rate 10r/s;

    # локальный слой на кадрах: до шины, на каждом спрошенном кадре
    waf_local_check ws_binary $waf_frame_opcode action=block response=ws_policy;
    waf_local_rate  $waf_conn_id rate=50r/s burst=20 count=frames
                    action=block response=ws_flood;

    waf_capture  frame:c2s body=64k;
    waf_inspect  frame:c2s ws_rules wave=0 timeout=5ms;
    waf_hold     frame:c2s gate;
    waf_frame_cache frame:c2s ttl=30s;     # повтор кадра шину не видит

    waf_capture  frame:s2c body=64k;
    waf_inspect  frame:s2c dlp_frames wave=0 timeout=5ms;
    waf_hold     frame:s2c monitor;
    waf_frame_sample 0.1;                  # только в monitor

    proxy_pass http://app;
}
```

# waf_frame_reassemble

Умолчание `off`. `on` — единица инспекции собранное сообщение, а не
фрагмент: резать сигнатуру между кадрами с `fin=false` иначе бесплатно.
Потолок сборки — `waf_body_limit` этой фазы, политика оттуда же:
`block` закрывает соединение 1009 «message too big», `pass` и `trim`
отдают собранное получателю как есть, а остаток сообщения идёт мимо
инспекции до `fin`.

Сборка идёт в буфере направления на месте: заголовки продолжений
выбрасываются, нагрузка подклеивается к первому фрагменту, и получателю
сообщение уходит **одним кадром** — RFC 6455 (5.4) разрешает
посреднику склеивать фрагменты. Приложение, которому важны границы
фрагментов, включать сборку не должно. Контрольные кадры между
фрагментами уходят вперёд сообщения сразу: ping не ждёт вердикта.

Со сборкой проверяется и порядок: продолжение без начала и новое
сообщение внутри несобранного — 1002. Без сборки порядок не
проверяется, как и раньше.

Для gRPC сборка до границы length-prefixed message обязательна:
границу задаёт протокол.

# waf_frame_control_rate

Умолчание `10r/s`, `off` снимает. Ping, pong и close не инспектируются
— содержимого нет, а сообщений на шине добавляют столько же. Частота
при этом сама по себе вектор, поэтому ограничивается локально: корзина на
направление соединения со всплеском в секунду частоты, и ping или pong
сверх него **не пересылается** — вырезается из потока, соединение
живёт. Close не ограничивается никогда. Отброшенные считаются в записи
сессии (`control_dropped`), первый отброшенный — строка WARN на
соединение.

# waf_frame_cache

```
waf_frame_cache frame|frame:c2s|frame:s2c ttl=<time>;
waf_frame_cache off;
```

Кеш вердикта по хешу полезной нагрузки, на сторону кадра. Кадры
повторяются: heartbeat подпротокола, служебные приветствия, одно и то же
сообщение приложения тысяче клиентов по `s2c` — и каждый такой кадр
стоил бы сообщения на шину, похода в обменник и работы инспектора, хотя
ответ на него уже известен. Ключ — маршрут (сервер, путь, uuid),
сторона, опкод и SHA-256 нагрузки; попадание — `allow` без единого
сообщения на шину, в логе `reason "FRAME_CACHE"`, в записи кадра
`cached: true`, в записи сессии `frames_cached`. Таблица общая для
воркеров узла, поэтому требует `waf_shm_zone`; размер фиксирован
(4096 записей), вытесняется ближайшая по сроку. `ttl=` обязателен и
не больше часа.

Управляемость — в том, что попадает в кеш. Только чистый `allow`
**настоящей** инспекции: без счёта, без подмены, без правок заголовков
и cookie, без просьб соседям, без сорванных политикой или пропущенных
инспекторов. `deny` не кешируется никогда: отказ закрывает соединение,
и повторять его по хешу значило бы закрывать соединения без инспектора
и без записи находок. Инспектор вправе запретить кеш реплаем
(`"cache": false`, [verdict-protocol.md](../../verdict-protocol.md#ответ-инспектора)):
счётчик судит по корзинам, а не по содержимому, и его `allow` на N-м
кадре ничего не говорит про N+1-й — counter на кадрах так и отвечает.

Включать стоит там, где инспекторы судят по байтам (modsec, json,
rewrite без подмены) и где повторы есть. Смена профиля инспектора
кеш не сбрасывает: срок — единственный рычаг, поэтому он и ограничен
часом.

# локальный слой на кадрах

`waf_local_check` и `waf_local_rate` маршрута ([dataset_ext.md](dataset_ext.md))
бегут на каждом спрошенном кадре до шины. Проверки по наборам — все
строки маршрута, теми же словами: `allow` — кадр мимо инспекции,
`wave` — к волнам, `block` — соединение закрывается записью `response=`
(`type=websocket` даёт код и причину; иначе 1008 с именем правила). Так
адрес, попавший в бан посреди сессии, отсекается на следующем кадре, а
не при следующем рукопожатии. Лимиты считают кадры только с
`count=frames`; правила `requests` и `waves` на кадрах не смотрятся —
рукопожатие уже посчитано на своей фазе.

Переменные кадра для значений и ключей:

| Переменная | Значение |
| --- | --- |
| `$waf_frame_opcode` | `text`, `binary`, `continuation` |
| `$waf_frame_direction` | `c2s` или `s2c` |
| `$waf_frame_size` | полезная нагрузка, байт (у собранного сообщения — целиком) |
| `$waf_conn_id` | ray рукопожатия: ключ «на соединение» |

Вне фазы кадров все четыре пусты.

# waf_frame_sample

Доля кадров, уходящих на инспекцию. Умолчание `1.0`. Осмысленно
только при `waf_hold … monitor`: найденное закрывает соединение
целиком, и для сессионной защиты доли часто хватает. При `gate`
меньше `1.0` — `nginx -t`: это дыра в покрытии под видом настройки.

# waf_require_upgrade

```
waf_require_upgrade on|off [response=<name>];
```

Умолчание модуля `off`; контроллер печатает `on response=upgrade_required`
на каждом websocket-пути. Запрос без `Upgrade: websocket` на таком пути
отказывается локальным слоем, до шины не доходя: фазы ответа у пути нет,
и проксировать обычный GET значило бы отдать клиенту ответ, которого никто
не проверил. Запись отказа -- `response=` (426 в каталоге контроллера),
без неё -- умолчание маршрута. В аудите код `local_upgrade`, правило
`require_upgrade`.

# waf_ws_strip_extensions

```
waf_ws_strip_extensions <name> [<name>...] | all | off;
```

Снимает названные расширения из `Sec-WebSocket-Extensions` рукопожатия,
и приложение их не согласует. Согласованное расширение -- это кадры с
rsv-битами (`permessage-deflate` -- сжатые), которые обработчик кадров не
разбирает и пропускает мимо инспекции с одним предупреждением на
соединение; не дать согласовать дешевле, чем распаковывать в воркере, с
лимитами и поверхностью декомпрессионной бомбы. Остальные предложения
остаются; если не осталось ни одного, заголовок переименовывается в
`X-WAF-Stripped-Extensions` -- убрать запись из `headers_in` нельзя, прокси
копирует список как есть. Умолчание модуля -- не снимать; контроллер
печатает `permessage-deflate` на каждом websocket-пути, `off` снимает
унаследованное.

Цена -- рост трафика там, где сжатие давало выигрыш. Для чатоподобной
нагрузки с короткими сообщениями он и так невелик.

# состояние

Третья итерация обработчика кадров (06.09.2026,
`src/stream/ngx_http_waf_frame.c`): обе стороны, режим `gate`, один
кадр в полёте на соединение (на оба направления вместе), подмена
полезной нагрузки по секции `rewrite`, сборка фрагментов
(`waf_frame_reassemble`), локальный слой на кадрах, ограничитель
контрольных кадров (`waf_frame_control_rate`) и кеш вердикта
(`waf_frame_cache`). Что из фазовых семей исполняется:

| | |
| --- | --- |
| `waf_inspect frame:c2s`, `frame:s2c`, `frame` | работают; `frame` настраивает оба слота одной строкой; направление без волн идёт мимо инспекции, но через разбор кадрирования |
| `waf_capture frame[:dir] body=` | работает; полезная нагрузка едет локатором обменника |
| `waf_archive frame[:dir] body[=size] [ttl=] [when=]`, `waf_preview frame[:dir] body=size` | работают поверх снимка кадра: объект остаётся агенту только вместе с записью кадра (`waf_audit_frames`), срез ложится в `body_preview`. Могут быть **шире снимка** (весь кадр в буфере, масок нет; потолок — `waf_body_limit frame`); `reload` у кадра нет — `nginx -t`. `waf_preview frame body=<size> source=sent` кладёт в запись доставленную версию подменённого кадра, оригинал остаётся в архиве ([archive.md](archive.md#на-фазе-кадров), [preview.md](preview.md#sourcesent--что-показать-при-подмене)) |
| `waf_hold frame[:dir] gate` | работает; `monitor` на любой стороне — `nginx -t` |
| `waf_deadline frame`, `waf_score_deny frame[:dir]`, `waf_deny_mode` | работают через общую машину слотов |
| `waf_body_limit frame[:dir]` | `block` закрывает соединение 1009; `pass` и `trim` пропускают кадр мимо инспекции целиком; он же — потолок объекта подмены |
| `waf_deny_response … type=websocket` | код и причина кадра Close; запись другого типа — 1008 с кодом причины инспектора |
| `waf_require_upgrade`, `waf_ws_strip_extensions` | работают: отказ 426 без апгрейда, снятие расширений на рукопожатии |
| `waf_send frame[:dir] body=original\|store` | работает: откуда отдать нагрузку кадра второй стороне — как пришла или объект инспектора из обменника ([send.md](send.md)). Снимок взял префикс кадра, инспектор прислал подмену — сбой подъёма, и решает его `waf_exception <направление> body` (Close по deny, кадр как пришёл по pass): опции «отдать кусок» нет, `on_error=` и `waf_on_partial_rewrite` сняты |
| секция `rewrite` реплая | подмена полезной нагрузки кадра объектом `<node>:<rid>:frm:<суффикс>`; кадр собирается заново с опкодом и fin оригинала, у `c2s` — с маской оригинала |

| `waf_frame_reassemble on` | работает: сообщение собирается в буфере направления и уходит получателю одним кадром; потолок и политика — `waf_body_limit frame`; продолжение без начала и сообщение внутри сообщения — 1002 |
| `waf_local_check`, `waf_local_rate … count=frames` на кадрах | работают: до шины на каждом спрошенном кадре, с переменными `$waf_frame_opcode`, `$waf_frame_direction`, `$waf_frame_size`, `$waf_conn_id`; отказ — Close записью `response=` |
| `waf_frame_control_rate` | работает: ping/pong сверх частоты не пересылаются, умолчание 10r/s |
| `waf_frame_cache frame[:dir] ttl=` | работает: чистый allow настоящей инспекции по хешу нагрузки, требует `waf_shm_zone`; `"cache": false` в реплае запрещает; кадр с выключенным (`state: off`) инспектором не запоминается |
| `waf_inspect frame … mode=off` и глаголы `active`/`passive`/`off` с осью `conn` | работают: ось `request` — этот кадр, `conn` — до конца соединения; первый кадр наследует состояние рукопожатия ([inspect.md](inspect.md#modeoff)) |

Из директив **этой страницы** модуль по-прежнему не принимает
`waf_frame_sample`: без `monitor` выборке негде работать. Принятая и не
исполняемая директива хуже отсутствующей.

# правила

- фаза кадров без `waf_inspect frame:c2s …` не поднимается: обработчик
  апгрейда стоит денег, включать его «на всякий случай» незачем
- `redirect` в кадре запрещён: перенаправлять некого
  ([verdict.md](verdict.md)); присланный `redirect` закрывает
  соединение как `deny`
- счёт живёт в пределах кадра. Подозрительность сессии — дело
  инспектора: он видит `conn_id` и волен вести своё состояние
- контекст рукопожатия инспектор получает секциями `conn` / `http` /
  `request_store`, как на фазе запроса: соединение живо, копировать
  рукопожатие в каждый кадр незачем
- `waf_store ttl=` обязан покрывать жизнь соединения, иначе объекты
  рукопожатия станут `unavailable` посреди сессии
- канал действий работает внутри кадра: просьба первой волны видна
  второй (счётчик просит rewrite отвечать ошибкой -- `do: mutate`), а
  набор рукопожатия остаётся в `prior`; между кадрами просьбы не
  переносятся -- живой набор кадра живёт в его пуле и умирает вместе с ним
- локальный слой и кеш бегут только на кадрах, которые инспектируются:
  направление без волн идёт мимо и того, и другого
- аудит кадра — запись агенту по политике `waf_audit_frames off|deny|all
  [sample=n]` (умолчание `deny`: отказ, подмена, счёт) и запись на сессию
  при закрытии соединения; всё соединение под ray рукопожатия, кадр
  адресуется стороной и номером
  (`docs/audit.md`, «Кадры»); строки лога на кадр и на закрытие остались
