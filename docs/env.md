# Окружение процессов: адреса инфраструктуры

Правило владельца от 23.08.2026: **адрес узла инфраструктуры — топология развёртывания,
поведение по отношению к нему — настройка панели.** Адрес приходит окружением и не правится из
UI; сроки, пределы, таймауты и имена бакетов правятся из UI и не приходят окружением.

Здесь правило доведено до контракта: какие имена, в каком порядке читаются, что процесс делает,
когда адреса нет, и чего в умолчаниях не бывает никогда. Кто читает какие переменные целиком —
в README компонентов; как это выглядит в манифестах — в [install.md](install.md); производство
образов — в [delivery.md](delivery.md).

## Цепочка источников

Первый непустой выигрывает:

1. **`WAF_<КОМПОНЕНТ>_<УЗЕЛ>_URL`** — персональное переопределение: одна копия ходит не туда,
   куда весь контур. Нужно редко и обязано быть возможным (перевод одной реплики на свежий
   Redis, отладка копии против другой шины).
2. **`<УЗЕЛ>_URL`** — контурная переменная: `NATS_URL`, `REDIS_URL`, `REDIS_INTERNAL_URL`,
   `S3_ENDPOINT`, `DATABASE_URL`, `CLICKHOUSE_ADDR`. Одна запись в `x-infra` у compose или в
   ConfigMap у Kubernetes заводит десяток процессов.
3. **Файл компонента** — `inspector.conf` (блок `redis`), `agent.conf`. Есть не у всех; там, где
   есть, окружение его перекрывает, а не наоборот: окружение — свойство запуска, файл — свойство
   образа.
4. **Встроенное умолчание** — имя сервиса из compose (`nats://nats:4222`). Годится ровно для
   одной машины; в промышленной установке всё называется явно.

Цепочка не выдумана: так уже сделаны `keeper` (`WAF_NATS_URL` → `NATS_URL` → умолчание) и
контроллер (`CONTROLLER_NATS_URL` → `NATS_URL` → умолчание). Остальным её надо дописать.

## Узлы контура

Имена «сегодня» — то, что читает код на 12.09.2026; расхождение и есть проблема.

| Узел | Кто ходит | Имена сегодня | Контурное имя |
| --- | --- | --- | --- |
| Шина NATS | все | `NATS_URL` (Go-инспекторы, vlai), `WAF_NATS_URL` (keeper, geo, crypto, logger, все агенты), `CONTROLLER_NATS_URL` + `_USER`/`_PASS`/`_TOKEN` (контроллер) | `NATS_URL` |
| Redis-обменник | инспекторы, модуль, агент ноды, контроллер | `REDIS_URL` и блок `redis { url }` (инспекторы), `WAF_REDIS_URL` (агент ноды), `CONTROLLER_REDIS_URL` (контроллер, он же печатает `waf_store url=` в конфиг модуля) | `REDIS_URL` |
| Внутренний Redis | инспекторы, keeper, контроллер, агент ноды | `REDIS_INTERNAL_URL` и блок `redis { internal }`, `WAF_KEEPER_REDIS_URL`, `WAF_REDIS_INTERNAL_URL`, `CONTROLLER_REDIS_INTERNAL_URL` | `REDIS_INTERNAL_URL` |
| S3 | агент S3, logger, агент ноды (выгрузка архива) | `S3_ENDPOINT`/`S3_ACCESS_KEY`/`S3_SECRET_KEY`/`S3_BUCKET`/`S3_REGION`, `WAF_STORE_S3_*` + `WAF_STORE_BUCKET_*`, `WAF_RETAIN_S3_*` + `WAF_RETAIN_BUCKET_*` | `S3_ENDPOINT`, `S3_REGION`, реквизиты — файлом |
| PostgreSQL | контроллер, keeper, logger (подстановки словарей) | `CONTROLLER_DATABASE_URL`, `WAF_KEEPER_DATABASE_URL`, `POSTGRES_HOST`/`_PORT`/`_USER`/`_PASSWORD`/`_DB` | `DATABASE_URL` |
| ClickHouse | logger, search | `CLICKHOUSE_ADDR` (у логгера `WAF_CH_ADDR` рядом), `CLICKHOUSE_USER`, `CLICKHOUSE_PASSWORD` | `CLICKHOUSE_ADDR` |
| Кодер гео | инспекторы с записью `net`/`net_all`/`asn` | `WAF_<ИНСПЕКТОР>_GEO_ADDR` | так и оставить: это не общий узел, а адресат одной функции |

Четыре схемы имён для одних и тех же шести адресов — это не стиль, это способ развести контур
молча: модуль кладёт объект в один Redis, инспектор читает из другого, и наружу это выходит как
`store_error` у инспектора и `expired` в аудите.

## Деградация: что процесс делает без адреса

Умолчание — это не только «какой адрес», но и «что будет, если его нет». Три класса, четвёртого
быть не должно.

| Класс | Когда | Поведение |
| --- | --- | --- |
| **Жёсткий отказ** | без узла процесс бессмысленен | не стартовать, внятная строка, выход с ненулевым кодом; контейнер перезапустится |
| **Мягкая потеря** | без узла процесс делает свою работу, но не всю | стартовать, `WARN` в журнале при старте, функция отвечает отказом с машинным кодом |
| **Объявленная подмена** | есть законный запасной адрес | работать, но кричать: `WARN` со словами «взят запасной», и это обязано быть видно в пульсе, а не только в логе |

Как это выглядит у инспектора действий — он проверен целиком и годится за образец:

| Нет адреса | Класс | Что именно |
| --- | --- | --- |
| Шина (`NATS_URL`) | жёсткий | `startup failed: dial tcp: lookup nats: i/o timeout`, выход. После первого успешного подключения — наоборот, бесконечные переподключения: инспектор переживает перезапуск шины, а не умирает вместе с ней |
| Обменник (`REDIS_URL` пуст) | мягкая потеря | `WARN object store is not configured`; условия по заголовкам, кукам и аргументам считают объект недоступным, поля сообщения и `vars` работают |
| Обменник назван, но недостижим | жёсткий | `Ping` на старте — отказ. Осознанно: недостижимое хранилище должно ловиться стартом, а не первым условием посреди боя |
| Внутренний Redis (`REDIS_INTERNAL_URL` пуст) | подмена | `WARN internal redis falls back to the exchange` — зеркало наборов поедет из обменника. Рабочий режим установки с одним Redis и забытый адрес на контуре с двумя выглядят одинаково, отличает их только эта строка |
| Кодер гео (`WAF_ACTION_GEO_ADDR` пуст) | мягкая потеря | записи в набор с `write: net`/`net_all`/`asn` отвечают `ACTION_GEO_UNAVAILABLE`, обычный адрес пишется как обычно |
| Приёмник журнала (`WAF_LOG_SHIP=off`) | мягкая потеря | журнал остаётся только в stdout контейнера |

Чего быть не должно — **тихой подмены хранилища**. У S3, ClickHouse и Postgres запасного адреса
не бывает: записать событие не туда хуже, чем не записать. Там правило другое — очередь,
отказ с кодом и видимый счётчик потерь.

## Реквизиты — не адреса

Пароли, ключи S3 и токены шины умолчаний не имеют. Забытый адрес — сломанный контур, забытый
пароль с умолчанием — контур, подключившийся не тем и не туда.

Два нарушения в дереве на сегодня, оба стендовые по происхождению:

- `keeper`: `WAF_KEEPER_DATABASE_URL` с умолчанием `postgres://waf:waf@postgres:5432/waf` прямо
  в коде;
- `logger`: подстановки `${POSTGRES_USER}`/`${POSTGRES_PASSWORD}` в миграциях словарей падают в
  `waf`/`waf`.

Правильная форма: реквизиты — файлом (`*_CREDENTIALS_FILE`, как у S3 в логгере и агенте ноды)
или переменной без умолчания, и пустое значение — жёсткий отказ с внятной строкой.

## Что остаётся в панели

Не адрес, а поведение: сроки и пределы обменника (`ttl`, `retain_ttl`, `max`, `pool`,
таймауты), имя пространства и `pending_max`/`payload_max` у шины, эндпоинт, регион, бакеты и
темп выгрузки у агента S3 (`/config/agent`, KV `policy/agent-conf`). Адреса панель показывает
на чтение (блок `infra.nats_url` в `GET /api/<scope>/http`) — и не принимает на запись.

S3 из правила выпадает и настраивается целиком: потребитель у него один — агент, и канал
доставки настроек для него уже есть.

## Главный риск: адреса разошлись

Один и тот же адрес сегодня объявлен трижды: компилятор печатает его в шаблон nginx из
окружения контроллера, агент ноды читает свой `agent.conf`, инспектор — своё окружение. Правка
одного разводит их молча.

Предложение, которое закрывает это малой кровью: **процесс сообщает действующие адреса в кадре
пульса** (с вырезанными реквизитами — `url.Redacted()` в дереве уже есть), а страница
«Состояние» сверяет их с тем, что напечатал компилятор. Расхождение становится жёлтой строкой
на странице вместо `store_error` в журнале через неделю. Кадр пульса уже возит `config_hash`,
`rev` и `apply` — место для трёх адресов там есть.

## План приведения имён

Совместимо и без единовременной раскатки: старое имя остаётся первым звеном цепочки, новое
добавляется следующим. Ни одна установка от этого не ломается.

| Компонент | Что добавить |
| --- | --- |
| Go-инспекторы | `WAF_<ИМЯ>_NATS_URL` → `NATS_URL`; `WAF_<ИМЯ>_REDIS_URL` → `REDIS_URL`; `WAF_<ИМЯ>_REDIS_INTERNAL_URL` → `REDIS_INTERNAL_URL` → блок `redis` |
| Агенты (`nginx`, `s3`, `redis`, `haproxy`) | `WAF_NATS_URL` → `NATS_URL`; `WAF_REDIS_URL` → `REDIS_URL`; `WAF_REDIS_INTERNAL_URL` → `REDIS_INTERNAL_URL` |
| keeper | `WAF_KEEPER_DATABASE_URL` → `DATABASE_URL`, умолчание с реквизитами убрать |
| logger | `WAF_CH_ADDR` → `CLICKHOUSE_ADDR`; `POSTGRES_*` → `DATABASE_URL`, умолчания реквизитов убрать |
| controller | `CONTROLLER_DATABASE_URL` → `DATABASE_URL` |
| vlai | `REDIS_URL` у пробы и у процесса — один источник (сейчас проба читает только окружение и не видит `inspector.conf`) |

Порядок работ привязан к разложению компонентов по веткам ([delivery.md](delivery.md)): каждый
компонент приводит имена в тот же заход, когда получает свою ветку и образ. Отдельной
раскатки «переименуем всё разом» не будет — она означала бы одновременный рестарт контура.
