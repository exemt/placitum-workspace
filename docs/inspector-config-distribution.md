# Распространение конфигурации инспекторов

Инспекторы возят конфигурацию через KV одним и тем же способом: modsec — наборы
правил SecLang, [auth](inspectors/auth/README.md#профили-из-контроллера) —
профили калитки второго фактора, капча — свои профили и страницу,
[json](https://github.com/exemt/placitum-json/blob/develop/docs/README.md#профили-из-контроллера) — профили контракта
вместе с текстом спецификации. Отличаются они только ключом и содержимым
файлов; всё остальное — три слоя, канон хеша, сходимость флота — общее.

| | modsec | auth | json |
| --- | --- | --- | --- |
| Ключ KV | `policy/modsec` | `policy/auth` | `policy/json` |
| Файлы профиля | `NN-имя.conf`, SecLang | `profile.yaml`, `users.yaml` | `profile.yaml`, `schema-<имя>` |
| Что читает файлы | Coraza | тот же загрузчик, что читает каталог с диска | тот же загрузчик; спеку компилирует при загрузке |
| Секреты | нет | ссылки `store:<uuid>`, открывает форма входа ключом контура | нет |
| API | `/rules/send`, `/rules/desired` | `/auth/send`, `/auth/desired` | `/json/send`, `/json/desired` |

Ниже — разбор на примере modsec.

## Распространение правил инспектора modsec

Черновик файлов и профилей живёт в Postgres. Разослать поколение на реплики
`inspector-modsec` — операция `send`. Инспектор сам смотрит JetStream KV, собирает
дерево, компилирует Coraza и атомарно подменяет набор. Sidecar-агента нет: инспектор
уже процесс на Go с NATS, ему не нужен посредник на ноде nginx.

CRS по-прежнему образ сервиса (`coraza-coreruleset`, `Include @owasp_crs/...`).
В KV едут только локальные файлы профилей. Секретов в SecLang нет, `store:` не нужен.

Раскатка шаблона nginx — другой контур, см. [config-distribution.md](config-distribution.md).
Списки адресов — третий, JetStream в shm, см. [inspectors.md](inspectors.md#поставщик-данных).

## Три слоя

Сохранить черновик ≠ разослать.

1. **Черновик.** Оператор правит `rule_files` и составы `rule_sets`. Listener пишет
   `draftChanged`, в шину ничего не уходит.
2. **Поколение.** `POST /api/<scope>/rules/send` собирает все профили пространства,
   считает `config_hash`, пишет манифест в KV `WAF_DESIRED/policy/modsec`.
3. **Apply.** Каждая реплика пишет staging, компилирует, при успехе меняет указатель
   `Set`. Ошибка любого профиля — отказ всего поколения, боевой набор не трогать.

## Манифест

Ключ — `policy/modsec` в бакете `WAF_DESIRED` (тот же, что у nginx). Один ключ на
контур. Несколько `http_spaces` на одной шине — тогда ключ
`WAF_DESIRED/<scope>/policy/modsec`; сейчас в выкладке одно пространство.

```json
{
  "v": 1,
  "rev": 12,
  "config_hash": "sha256:…",
  "profiles": {
    "default": {
      "files": [
        { "name": "00-engine.conf", "text": "…" },
        { "name": "30-policy.conf", "text": "…" }
      ]
    }
  },
  "settings": { "log_level": "info" }
}
```

`settings` — свойства самого процесса, см. [«Настройки процесса»](#настройки-процесса).
Блока может не быть: поколение старого контроллера его не несёт.

Профиль = `rule_set`. Имя набора — тег `profile=` записи реестра (`route.profile`). Файлы в манифесте
идут в порядке `rule_set_files.position`; имя файла —
`{position:02d}-{имя}.conf`, чтобы лексический `Glob` совпал с `position`.

Контроллер не оборачивает тексты скелетом `00-engine` / CRS: `Include @owasp_crs/...`
и `SecRuleEngine` пишет оператор (или сиды). Набор с именем `default` обязателен —
без него `send` отвергается на контроллере.

`rev` растёт на каждый успешный `send`. Откат — повторный `send` предыдущего
состава; инспектор историю сам не хранит.

## `config_hash`

SHA-256 канонического снимка `profiles`, не всего манифеста. Канон — не JSON
(экранирование `<`/`&` разъедется между языками), а конкатенация UTF-8:

```
для каждого имени профиля в лексическом порядке:
  имя профиля, байт 0
  для каждого файла по порядку:
    имя файла, байт 0
    текст файла, байт 0
если в манифесте есть блок settings:
  "settings", байт 0
  "log_level", байт 0
  значение, байт 0
```

Префикс `sha256:`, дальше hex. Секретов в хеш не входит — их нет.

Секция `settings` входит в канон ровно тогда, когда блок есть в манифесте: поколение
без него хешируется как раньше, и инспектор, читающий старый манифест, сходится с его
`config_hash`. Список ключей секции прибит (сейчас один — `log_level`); новый ключ — новый
канон, и инспекторы обязаны узнать о нём раньше контроллера, иначе первый же `send`
после обновления контроллера оставит их в `apply_failed` (Go отвергает манифест с
чужим `config_hash`) либо в вечном `drift` (vlai применяет и докладывает посчитанное).

У паков `rules` и `ip` (указатель в KV, тела в Redis) секция та же и стоит последней —
после `policies` у правил и после `profiles` у адреса. Прибитое число для сверки трёх
реализаций: `controller/src/inspector-settings.test.ts`,
`inspectors/action/internal/desired/settings_test.go`, `inspectors/vlai/tests/test_profiles.py`.

## Настройки процесса

Профили — файлы: они ложатся на диск, и их читает загрузчик. Настройки — свойства самого
процесса из каталога инспекторов (`inspectors.log_level`, панель «Инспекторы → Каталог»):
файлом не ложатся, применяются к процессу напрямую и живут только в памяти. Сейчас настройка
одна — уровень журнала.

Зачем она едет поколением, а не переменной окружения. Инспектор на `info` пишет строку на
каждое сообщение шины; под нагрузкой это стоило инспектору действий половины пропускной
способности, а превышение оборачивается не backpressure, а тихой потерей сообщений
(`nats: slow consumer, messages dropped`) и `500` по дедлайну у модуля. Переменная
`WAF_<ИМЯ>_LOG` меняется только рестартом контейнера, который под прогоном обнуляет
прогон. Поэтому:

- **словарь** — `error_log` nginx без `emerg`: `debug`, `info`, `notice`, `warn`,
  `error`, `crit`, `alert`. Те же слова на краю и у инспектора. Сам инспектор пишет
  только `debug`/`info`/`warn`/`error`: `notice` режет то же, что `warn`, а `crit` и
  `alert` глушат его журнал целиком;
- **источник** — строка каталога по имени процесса (`consumer.name` канала: `modsec`,
  `ip`, `auth`, …). Сборщик поколения читает её из Postgres тем же источником, что и
  планировщик сходимости, — иначе план и рассылка разошлись бы в хеше;
- **доставка** — правка каталога сохраняется как черновик; канал процесса показывает
  расхождение, и значение уезжает следующим `send` этого канала вместе с профилями. Блок
  входит в `config_hash` намеренно: иначе флот не заметил бы правку;
- **применение** — процесс держит порог в `slog.LevelVar` (Go) либо в модуле `log`
  (vlai) и переставляет его после успешного `apply` поколения, без рестарта. Битое
  поколение уровень не меняет — оно отвергается целиком. Переменная окружения задаёт
  стартовое значение и действует до первого поколения с блоком; блока нет — порог не
  трогается;
- **рестарт** — на диске уровень не хранится; после старта процесс работает на значении из
  окружения, пока watch не отдаст текущее поколение из KV (это первое же событие watch).

Чужое слово в `log_level` — отказ всего поколения (`apply_failed`): контроллер такого не
шлёт (словарь прибит ограничением в базе), значит в KV положили руками.

**Порядок раскатки.** Сначала инспекторы, потом контроллер. Новый инспектор со старым
контроллером работает как раньше (блока нет — легаси-канон). Новый контроллер со старым
инспектором после первого `send` оставляет его в `apply_failed`: старый код считает хеш
без секции и не сходится с `config_hash`. Сразу после обновления контроллера все каналы с
инспектором показывают расхождение — блок появился в каноне у всех разом; это лечится
одним `send` на канал.

Объём — килобайты. Если когда-нибудь не влезет в `max_payload` KV, тело остаётся
в Postgres, в KV — hash и указатель. Лимит кадра горячего пути не поднимают.

## Что делает инспектор

Не sidecar. Watch KV на уже существующем соединении с шиной.

1. Старт: диск `WAF_MODSEC_PROFILES` (как сейчас). Если в `WAF_MODSEC_DATA` уже
   лежит применённое дерево с `request/default` — поднять его: рестарт без KV
   (или пока watch не догнал) не откатывается на bootstrap.
2. Нет поколения в KV — так и работаем. Локальные тесты и `tests/modsec`
   не ломаются.
3. Появилось поколение: распаковать в staging рядом с боевым деревом данных,
   не поверх `WAF_MODSEC_PROFILES` (тот том в compose только для чтения).
4. Подмена каталога, `Reload()` с нового пути. Провал компиляции — откат дерева,
   `apply=apply_failed`, в пульсе **старый** hash.
5. Успех — указатель `Set` сменён, пульс: `config_hash`, `rev`, `apply=ok`,
   список имён профилей. Тогда же применяется блок `settings`: порог журнала
   переставляется на ходу.

`WAF_MODSEC_DATA` по умолчанию — сосед `profiles.applied`. В контейнере это
записываемый слой образа, не git-дерево профилей.

### Замена горячая: чем это проверено

Сборка набора идёт в горутине watch, а не на горячем пути, и стоит она заметно:
пять профилей и 1337 правил собираются около 1.3 с процессорного времени
(`internal/rules.build`). Всё это время трафик судит **прежний** набор — новый
публикуется одним `Store` указателя, а старый снимок доживает до конца взятых
им транзакций.

Проверяет это нагрузочный кейс `modsec-swap` (`tests/load`): ровный темп, в
середине каждой ступени правка правила и `send`. Правило-сторож стоит во всех
поколениях и обязано отказывать в каждой пробе — им ловится окно, в котором
маршрут не проверялся бы ничем. Замеры стенда — 400 rps, пять копий
инспектора, три прогона со сменами и три отсчётных (`--no-swap`):

| Что | Сколько |
| --- | --- |
| новое правило видно через край | 73–461 мс (15 смен) |
| подтверждено устойчиво | 0.6–1.0 с, включая цену подтверждения |
| разброс между копиями по журналу `desired applied` | 10–30 мс |
| пропусков сторожа на ~370 проб | 0 |
| отказов модуля (`fail=`) в пробах | 0 |

Просадки не видно. p50 не двигается вовсе (3–5 мс со сменами и без), а хвост
p99 гуляет 6–36 мс одинаково в обеих сериях: худшая ступень отсчётных прогонов
19/32/36 мс, прогонов со сменами — 25/27/87 мс. Единственный выброс 87 мс
одиночный, и объяснить его заменой нельзя, пока отсчёт без единой замены даёт
36 мс. Правильный вывод из этих цифр — «на этом стенде и на этом темпе просадка
не отделяется от собственного разброса стенда», а не «просадки нет».

## Сходимость флота

Не по факту `send`. Desired — `config_hash` в KV. Actual — heartbeat инспектора.

```text
WAF_STATUS.inspector.<имя>.<id>
```

Флот переехал, когда все живые кадры `inspector.modsec.*` репортят desired hash.
Молчание за TTL — дыра, не успех.

| Состояние | Смысл |
| --- | --- |
| `ok` | actual = desired |
| `drift` | desired новый, actual старый |
| `apply_failed` | манифест доехал, компиляция нет; hash не обновлён |
| `unknown` | нет desired или реплика ещё на bootstrap без hash |

Откат — `send` предыдущего состава.

## API контроллера

Пространство в пути, не в query и не в теле.

| Метод | Назначение |
| --- | --- |
| `GET /api/<scope_uuid>/rules/desired` | Текущий манифест из KV; нет поколения — `404` |
| `POST /api/<scope_uuid>/rules/send` | Собрать из Postgres, проверить `default`, записать KV |

Сохранение файла и набора по-прежнему только черновик.

Ошибки `send`: `missing_default`, `empty_profile`, `invalid_profile_name`,
`no_profiles`, `kv_unavailable`.

## Чего сюда не кладут

- CRS и `@coraza.conf-recommended` — зависимость образа.
- Шаблон nginx и PEM — [config-distribution.md](config-distribution.md).
- Наборы `waf_local_dataset` — снапшот JetStream в shm.
- Дельты одного файла: компиляция всё равно целиком.
