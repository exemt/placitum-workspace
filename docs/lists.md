# Списки локального слоя

Именованный набор в shared memory модуля и строка каталога контроллера — одна
сущность. Состав живёт в Postgres; на край едет снапшотом и дельтами JetStream,
без reload nginx. Воркер базу не читает.

Раскатка `nginx.conf` сюда не входит: директивы объявляют слот, не записи.
См. [config-distribution.md](config-distribution.md),
[inspectors.md](inspectors.md#поставщик-данных).

## Связка

| Контроллер | Модуль |
| --- | --- |
| `datasets.id` | `waf_local_dataset … uuid=` |
| `datasets.name` | имя директивы и поле `"dataset"` |
| `type` `ipv4`/`ip` | `type=cidr` |
| `type` `string`/`numeric` | `type=string` |
| `max_entries` | `max=` |
| `active` | живой: состав держит keeper, край подписан на `waf.sets.<name>` |
| `dataset_addresses` (`active=false`) | база internal-набора, едет конфигом |
| состав активного набора у keeper (Redis) | overlay: пакеты и снапшоты, [keeper.md](https://github.com/exemt/placitum-keeper/blob/develop/docs/spec.md) |

Без `uuid=` модуль по-прежнему стыкует слот по имени. С uuid слот переживает
переименование: данные не теряются.

## `active`

Галочка на списке (`kind=list`). Выключена — статический набор: состав
пишет контроллер, он едет конфигурацией (`in_nginx`) и паком адреса. Включена
— живой набор ([keeper.md](https://github.com/exemt/placitum-keeper/blob/develop/docs/spec.md)):

- состав держит keeper во внутреннем Redis; правка из панели — событие
  keeper с ответом, а не строка в базе, и панель читает состав из Redis;
- инспектора и модуль (автобан) пишут события на `waf.sets.<имя>.event`;
- keeper нумерует изменения, кладёт пакеты и снапшоты в Redis двоичными
  объектами, издаёт уведомления и тики, отвечает на снапшот ссылкой;
- все читают `waf.sets.<имя>` и объекты из Redis, в `.event` пишут только
  писатели.

`kind=content` флаг игнорирует: содержимое едет не шиной локального слоя, а вместе с
конфигурацией — телом в Redis по `sha256`, в каталог страниц ноды, см.
[deny-pages.md](deny-pages.md#дистрибуция).

## TTL

У активного набора запись всегда со сроком: `ttl` события, без него — `ttl`
набора, без обоих — отказ keeper `no_ttl`; вечных записей у активного набора
нет, постоянное едет холодным списком в конфиге (`active=false`). Объект
события:

```json
{ "value": "203.0.113.7", "ttl": 300 }
```

Просроченное в overlay — промах до пакета `remove EXPIRED` от keeper; край
сам записи не снимает, иначе разошёлся бы с keeper хешем.

## Два уровня в shm

База — плотные массивы, атомарный своп указателя, чтение без мьютекса; у
неё живёт только internal-набор, который приезжает конфигом. Overlay —
rbtree в slab на слот с rwlock слота: читатель берёт разделяемый замок,
применение пакета — исключительный. У активного набора overlay — весь
состав: пакеты keeper ложатся в него точечно, миллионный набор не
пересобирается ни на одну запись.

Ключ overlay — материал записи с провода: у адреса семейство, длина маски и
адрес под маской, у строки — она сама. Префикс с маской — такая же запись со
сроком, как одиночный адрес (`203.0.113.0/24` на час); поиск адреса пробует
только те длины масок, которые в наборе есть (счётчики по длинам), по одному
обращению к дереву на длину. Снапшот ложится пометкой и выметанием: записи
объекта кладутся порциями с новым поколением, затем всё с прежним снимается —
состав отвечает всё это время, дыры нет.

Разметка зоны (замок, поколение, счётчики длин) изменилась 11.09: после
выкладки нужен **restart**, не reload.

## Протокол шины

Истина активных наборов и единственный писатель их subject — keeper
([keeper.md](https://github.com/exemt/placitum-keeper/blob/develop/docs/spec.md)). Контроллер владеет определениями и докладывает
keeper о правках; инспектора, HTTP-процессы и модуль пишут события с ответом
на `waf.sets.<имя>.event`. Все зеркала — модуль в shm, `livelist` в auth и
captcha, `dyn` в ip — на одном проводе v3:

    waf.sets.<имя>            diff (ссылка на пакет) и tick от keeper (core NATS)
    waf.sets.<имя>.snapshot   ссылка на объект снапшота по запросу
    waf.sets.<имя>.event      запись с ответом {ok, seq, epoch} либо отказом

Состав по шине не едет: пакеты `waf:diff:<имя>:<seq>` и снапшоты лежат во
внутреннем Redis двоичными объектами `WAFS`, зеркало читает их само
(`waf_sets_store` у модуля, `internal` блока `redis` у инспекторов).

Кадр несёт `(epoch, seq, hash)`; хеш — XOR SipHash-2-4 по материалу записей под
ключом эпохи из снапшота, и зеркало сверяет его после каждой дельты и на
тике. Чужая эпоха или расхождение — снапшот, разрыв нумерации — пакеты
`свой+1…seq` из Redis по ключам. Истечение приходит пакетом `remove` от
keeper; зеркала по сроку не удаляют.

```json
{ "v": 3, "set": "banned_by_counter", "epoch": "9f2c…", "seq": 4182,
  "op": "diff", "hash": "c41e…",
  "package": "waf:diff:banned_by_counter:4182", "count": 1 }
```

Модуль: подписка на subject набора открывается транспортом вместе с
инбоксом (`SUB waf.sets.<имя>`), снапшот и хвост идут запросом с ответом в
подтему инбокса; страницы копятся в пуле сеанса и применяются разом. Право
просить разыгрывается в зоне: один воркер на ноду. JetStream в проводе
наборов не участвует.

Хеш в shm: overlay держит SipHash материала записи в узле, слот — `live_hash`
(XOR по узлам); у активного набора это и есть хеш состава, и он сверяется с
заголовком каждого пакета и с каждым тиком. Запись автобана этой ноды
ложится с нулевым хешем — его принесёт пакет keeper, который её подтвердит.

## Автобан с модуля

`waf_local_rate` с `list=` и `ttl=` после 429 кладёт ключ в overlay этой ноды
и, если запись новая или TTL удлинился, публикует событие:

```
waf.sets.<имя>.event
```

```json
{ "v": 1, "dataset": "ratelimited", "uuid": "…",
  "op": "add", "value": "203.0.113.7", "ttl": 300,
  "origin": "edge-01", "reason": "LOCAL_RATE", "ray": "…" }
```

Этот запрос уже закрыт rate (`response=` → 429). Список нужен следующим
запросам и другим нодам; событие уходит на `waf.sets.<имя>.event`, keeper
издаёт дельту, и она возвращается сюда же с каноническим текстом и хешем.
`waf_local_check` того же набора ставят выше rate.

У набора с `hash=md5` в overlay и в событии — md5 ключа в hex, и событие
несёт `"hashed": true`: keeper кладёт значение как есть. Писатель без
пометки (инспектор, скрипт) шлёт сырое, и md5 считает keeper. `hash=md5` у
самой `waf_local_rate` — про ключ корзины, не про набор: в набор уезжает
сырой ключ, а хеширует ли его набор, решает набор.

`action=pass` вместе с `list=` — ошибка `-t`.

События принимает keeper. Основной subject пишет только он. Соседи и
сторонние сервисы читают `waf.sets.<имя>`, не `.event`.

## Директивы

```nginx
waf_local_dataset <name> [type=cidr|string] [hash=md5] [limit=<n>] [ttl=<time>]
                  active|internal;

waf_local_rate <key> rate=… burst=…
               [action=block|pass] [response=<name>] [hash=md5]
               [list=<dataset> ttl=<time>]
               [if <значение> in|not in <набор>] …;

waf_local_check <dataset> <значение> action=block|allow|wave
                [response=<name>] [if …] …;

waf_local_check none;
waf_local_rate  none;
```

`none` снимает родительские правила: наследование заменой, и пустой
список отсутствием строк не выразить. Условия и селекторы запроса —
[directives/list/dataset_ext.md](directives/list/dataset_ext.md#условие-if).

Потолок overlay — 10000 записей. Темы у директивы нет: `waf.sets.<name>`
выводится из имени, `subject=` отвергает `nginx -t`.

Наборов в одной конфигурации — не больше 128, внутренние и активные
вместе (`NGX_HTTP_WAF_MAX_DATASETS` в `nginx/module/src/ngx_http_waf.h`).
Сверх него `nginx -t` падает на каждом краю с `waf: at most 128 datasets
may be declared`, поэтому контроллер такое поколение не собирает: превью
и `send` отвечают `datasets_too_many` с числом и пределом. Наборы с
`in_nginx=false` в счёт не входят. Предел в контроллере —
`NGINX_MAX_DATASETS` в `controller/src/model/http-space.ts`, меняется
вместе с заголовком.

стенда: запись событием, дельта на всех краях, `waf_local_check`, снятие,
