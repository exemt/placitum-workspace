# Инспектор → модуль

Ответ на сообщение волны: JSON в тот inbox, который модуль назвал в `reply-to`.

```
PUB waf.req.<имя>  _INBOX.waf.<node>.<pid>.<nonce>.v.<rid>.<ii>
```

Разбирать адрес инспектору не нужно — он отвечает на то, что стоит в `reply-to`. Правила протокола
целиком — [verdict-protocol.md](../verdict-protocol.md#ответ-инспектора); здесь собраны формы, в
которых он реально ездит, по одной на каждую секцию.

Значения в примерах те же, что в [examples/](examples): узел `nginx-1`, слот
`480000013b000000`, запрос `POST https://shop.example.com/api/orders`.

## Каркас

Полного набора в одном сообщении не бывает: секции взаимоисключающие по фазам и вердиктам. Но
множество полей такое:

```json
{
  "v": 2, "rid": "480000013b000000", "inspector": "modsec",
  "verdict": "allow|score|deny|redirect|error",
  "score": 0,
  "reason": { "code": "…", "scope": "…", "subject": "…", "retry": 0 },
  "response": { "name": "blocked" },
  "redirect": { "url": "…", "status": 303 },
  "headers":  { "set": {}, "unset": [] },
  "args":     { "set": {}, "unset": [] },
  "rewrite":  { "body": { "key": "…", "size": 0, "sha256": "…" },
                "content_type": "…", "groups": [] },
  "cookies":  [ { "name": "…", "value": "…", "path": "/", "max_age": 300 } ],
  "sessions": [ { "source": "…", "kind": "own|jwt|app", "user": "…", "id": "…" } ],
  "continue": { "subject": "…", "ttl_ms": 30000 },
  "actions":  [ { "to": "…", "do": "…", "apply": "…", "code": "…" } ],
  "cache": false
}
```

| Поле | Что это |
| --- | --- |
| `verdict` | Решение: `allow`, `score`, `deny`, `redirect`; `error` — «проверить не смог», признанное отсутствие решения ([verdict-protocol.md](../verdict-protocol.md#вердикт-error)). Единственное поле, ради которого волна ждёт |
| `score` | Уверенность 0–100 при `verdict: score`. Порог применяет модуль, вес берётся из `waf_inspect` |
| `reason.code` | Машинный код для оператора: лог, диагностический заголовок, выбор записи каталога отказов. Клиенту не попадает |
| `reason.scope` / `subject` | Публичная сторона причины: что закрыто (`address`, `network`, `country`, `asn`, `session`, `request`) и чем это названо. Печатает страница отказа |
| `reason.retry` | Через сколько **секунд** клиенту повторять, см. [ниже](#пропуск-и-отказ) |
| `response.name` | Имя записи каталога `waf_deny_response` — не файл страницы: запись держит статус, тип и `page=@location`, а страницу отдаёт nginx |
| `redirect` | Цель перенаправления и код (`302`, `303`, `307`; умолчание `303`) |
| `headers` / `args` | Переопределение заголовков и пар строки запроса: `set` меняет либо дописывает, `unset` снимает |
| `rewrite` | Адрес объекта в обменнике, которым модуль подменит тело, см. [подмену](#подмена-тела-ответа) |
| `cookies` | Что поставить клиенту; атрибуты назначает `waf_cookie_defaults` маршрута |
| `sessions` | Чьи сессии инспектор увидел. Модуль не применяет — переносит в аудит |
| `continue` | Обещание держать состояние до поздней фазы, см. [продолжение](#продолжение) |
| `actions` | Просьбы соседям. Модуль переносит, но не исполняет — кроме тех, чей адресат он сам |
| `cache` | Можно ли повторить вердикт по хешу кадра (`waf_frame_cache`). Только фаза кадров |

Обязательны четыре поля: `v`, `rid`, `inspector` — эхо из вопроса, и `verdict`. `rid` не совпал или
`inspector` не в маске текущей волны — ответ отброшен; незнакомый `v` — тоже. Эхо берётся из
сообщения, а не из конфигурации сервиса: под каким именем этот процесс объявлен в nginx, знает
только само сообщение.

Каждый инспектор объявляет у себя лишь то, что действительно шлёт: у `ip` в структуре нет ни
`score`, ни `rewrite`, у `counter` есть `cache`, у `auth` — `cookies` и `sessions`.

| Инспектор | Структура `Reply` |
| --- | --- |
| ip | [protocol.go:435](../../inspectors/ip/internal/protocol/protocol.go) |
| rewrite | [protocol.go:409](../../inspectors/rewrite/internal/protocol/protocol.go) |
| auth | [protocol.go:407](../../inspectors/auth/internal/protocol/protocol.go) |
| counter | [protocol.go:513](../../inspectors/counter/internal/protocol/protocol.go) |

## Где что можно

| Секция | Фаза | Вердикт | Кто шлёт в контуре |
| --- | --- | --- | --- |
| `score` | любая | `score` | modsec, json, vlai |
| `reason` | любая | любой | все |
| `response` | любая | `deny` | ip, auth, captcha, modsec |
| `headers` | request, response | любой | auth, rewrite, captcha |
| `args` | request | `allow` | — |
| `rewrite` | request, response, frame | `allow`, `deny` | rewrite, auth, captcha |
| `cookies` | request | `redirect`, `deny` | auth, captcha |
| `sessions` | request | любой | auth |
| `continue` | request | любой | modsec, rewrite, counter |
| `actions` | любая | любой | ip, counter, modsec, json, vlai, action |
| `cache` | frame | любой | counter |

Права на подмену в реестре больше нет: `mutate=on` снят, секции `rewrite`, `args` и заголовки фазы
ответа принимаются от любой декларации.

## Пропуск и отказ

Минимальный ответ — вердикт и код причины. `reason` едет и на `allow`: «проверил, чисто» отличается
в аудите от «не проверял».

```json
{"v": 2, "rid": "480000013b000000", "inspector": "ip", "verdict": "allow", "reason": {"code": "IP_OK"}}
```

Отказ добавляет имя записи каталога `waf_deny_response` и публичную тройку причины — то же решение,
пересказанное клиенту ([deny-pages.md](../deny-pages.md)):

```json
{
  "v": 2,
  "rid": "480000013b000000",
  "inspector": "ip",
  "verdict": "deny",
  "reason": { "code": "IP_LIST", "scope": "network", "subject": "203.0.113.0/24" },
  "response": { "name": "blocked" }
}
```

`code` читает оператор в логе, `scope`/`subject`/`retry` — посторонний человек в браузере. Отсюда
разная строгость: непрошедшее публичное поле модуль гасит молча, вердикт остаётся в силе, а
негодное `response` или лишний байт в заголовке рвут весь ответ.

**`response` — запись каталога, а не страница.** Имя адресует строку `waf_deny_response`
([deny_response.md](../directives/list/deny_response.md)), а она держит всё остальное: `type=`
(`http`, `grpc`, `websocket`), `status=`, `page=@location` и гейт `params=`. Страницу по `@location`
отдаёт сам nginx через `error_page` и `$waf_deny_name` — модуль на `@` не ходит. Ни кода HTTP, ни
пути, ни готового HTML с провода не принимается вовсе; прислано имя записи неподходящего для
протокола типа — применяется умолчание этого протокола, а расхождение уезжает в аудит. Нет поля —
`waf_deny_response_default`.

**`retry` — срок в секундах, через который клиенту повторять.** Не миллисекунды и не абсолютное
время. Попадает в `$waf_deny_retry` и печатается страницей отказа фразой «Повторить можно через
600 с.» (в JSON-близнеце — полем `retry_after`). HTTP-заголовка `Retry-After` модуль из него не
делает: это текст для человека, а не машинный контракт.

Принимается `1..2592000` (30 суток); вне диапазона — поле гасится, вердикт остаётся. `0` и
отсутствие равнозначны и означают «срока никто не назвал»: страница про него молчит, а не пишет
«через 0 с» — ноль читался бы как «повторяйте прямо сейчас», то есть ровно то, чего отказ не
разрешает. Печать ещё и под гейтом `params=` записи каталога: нет `retry` в перечне — переменная
`not_found`, и страница прячет блок целиком.

Заполняет `retry` тот, кто знает срок: `waf_local_rate` с `list=` (это его `ttl=`) и любой
инспектор, приславший поле. IP фильтр его пока не шлёт — срок бана назначает инициатор по исходу, а
не то правило, что сработало на этом запросе.

## Счёт

Инспектор сообщает уверенность числом 0–100 и не берёт на себя решение — порог применяет модуль,
сложив вклады с весами строк `waf_inspect`.

```json
{
  "v": 2,
  "rid": "480000013b000000",
  "inspector": "modsec",
  "verdict": "score",
  "score": 60,
  "reason": { "code": "CRS_ANOMALY" }
}
```

`score: 0` допустимо и не равно `allow`. Дробное, отрицательное или больше ста — ответ
отбраковывается целиком, без подрезки до допустимого: подрезка превратила бы ошибку инспектора в
тихо неверное решение. Отрицательного вклада нет вовсе, счёт только растёт.

Обратно в волну это приезжает суммой и разбором по авторам:

```json
"score": { "total": 45, "deny_at": 100 },
"prior": [
  { "phase": "request", "wave": 0, "inspector": "modsec", "verdict": "score",
    "score": 45, "reason": { "code": "CRS_ANOMALY" } }
]
```

`score` — что легло в сумму: при `verdict: score` как прислано, у совещательного (`mode=vote`) с
`verdict: deny` — сто. Множителя на вызове нет, поэтому число одно.

## Заголовки

Фаза запроса, `allow`: правки ложатся на заголовки перед проксированием. На фазе ответа та же
секция правит заголовки ответа.

```json
{
  "v": 2,
  "rid": "480000013b000000",
  "inspector": "auth",
  "verdict": "allow",
  "reason": { "code": "AUTH_OK" },
  "headers": {
    "set": { "X-WAF-User": "alice", "X-WAF-Groups": "ops,dev" },
    "unset": ["X-Forwarded-User"]
  },
  "sessions": [
    { "source": "corp", "kind": "own", "user": "alice", "id": "k7f3…",
      "verified": true, "issued": 1757232000, "expires": 1757260800, "groups": ["ops"] }
  ]
}
```

Пустое значение в `set` — осмысленное: так стирается то, что прислал клиент. Белого списка имён нет,
но `Host`, `Authorization`, `Cookie`, `Content-Length`, `Transfer-Encoding`, `Content-Encoding`,
`Connection`, `Upgrade`, `Keep-Alive`, `TE`, `Trailer` и оба `Proxy-*` запрещены безусловно; CR, LF
или NUL в имени либо значении — расщепление ответа, реплай отбрасывается целиком.

На фазе ответа асимметрия по направлению: `set Content-Type` разрешён, `set Set-Cookie` запрещён,
`unset Set-Cookie` разрешён, `Location` и `Date` закрыты в обе стороны, `Content-Length` чинит сам
модуль.

Секция `sessions` от вердикта не зависит и модулем не применяется: она уезжает в `sessions[]` записи
аудита, чтобы журнал отвечал «кто это был» независимо от того, чья калитка стоит на маршруте.

## Строка запроса

Зеркало `headers` по именам пар; объектом строка не ходит.

```json
{
  "v": 2,
  "rid": "480000013b000000",
  "inspector": "cleaner",
  "verdict": "allow",
  "args": { "set": { "page": "1" }, "unset": ["debug", "token"] }
}
```

Байты в проводном виде: модуль ничего не декодирует, режет по `&` и сравнивает имена побайтно до
`=`. Кодирование — дело инспектора, а `&` в имени или значении, `=` в имени, пробел и управляющие
символы — битая форма. Только фаза запроса при `allow` и только при
`waf_send request args=store`.

## Подмена тела ответа

Байты в реплае не ездят никогда: инспектор кладёт объект в обменник и присылает адрес.

```json
{
  "v": 2,
  "rid": "480000013b000000",
  "inspector": "rewrite",
  "verdict": "allow",
  "reason": { "code": "REWRITE_APPLIED" },
  "headers": { "set": { "Content-Type": "text/html; charset=utf-8" },
               "unset": ["Server", "X-Powered-By"] },
  "rewrite": {
    "body": {
      "key": "nginx-1:480000013b000000:rsp:out",
      "size": 12345,
      "sha256": "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08"
    },
    "groups": ["mask_pii"]
  }
}
```

| Поле | Что это |
| --- | --- |
| `body.key` | Адрес объекта в обменнике: `<ключ тела фазы>` плюс короткий суффикс `[a-z0-9_-]{1,32}` — по соглашению `out` у подмены и `form` у тела отказа. Ключ производный от локатора, который приехал в сообщении: чужой объект так не заадресуешь |
| `body.size` | Точный размер в байтах. Расхождение с прочитанным — отказ подмены |
| `body.sha256` | Хеш содержимого hex-строкой. Необязателен, но при наличии сверяется после чтения |
| `content_type` | Тип содержимого для тела отказа фазы запроса, одна строка до 128 байт; умолчание `text/html; charset=utf-8`. На фазе ответа не читается — там тип правит секция `headers` |
| `groups` | Имена групп профиля, которые инспектор применил к этому объекту, до 16. Модуль их не толкует: они уезжают в лог и аудит, чтобы по записи было видно, чем именно текст изменён |

**`groups` — единица правки у инспектора, а не у модуля.** Группа в профиле `rewrite` — это условия
(статус, `content_type`, для кадров — направление и опкод) плюс операции над телом и заголовками:
`replace`, `remove`, `insert_before`, `set`/`unset` заголовка. Часть групп стоит `default: true` и
работает всегда, часть включается просьбой соседа — глагол `mutate` называет группу полем `group` и
сторону полем `set`, незнакомое имя даёт исход `unknown_group` в аудите. Так устроена, например,
маскировка PII: `action` увидел повод `PII_SUSPECT`, попросил включить `mask_pii`, и в реплае
приехало `"groups": ["mask_pii"]` — расписка о том, что применилось. Профиль и группы —
[inspectors/rewrite/README.md](../../inspectors/rewrite/README.md).

**Распоряжения на случай сбоя в секции нет.** Ключ пропал, размер разошёлся, снимок оказался
неполным — это ошибка обработки запроса, и решает её политика фазы `waf_exception … body`
(`block` — отказ, `pass` — оригинал с WARN), та же, что распоряжается всякой недоступностью объекта
обменника. Прежние поля `on_error` и `response` сняты вместе с одноимёнными опциями `waf_send`:
три рычага об одном расходились бы между собой, а инспектор о доступности объекта знает не больше
модуля.

Секция без `body` — законная: одни `groups` означают «смотрел, менять нечего».
`body` без `key` или без `size` — битый ответ.

Подмена случится при двух условиях: `waf_send` маршрута отдаёт версию
инспектора (`store`), снимок полный. `truncated: true` — сбой подъёма, как пропавший ключ: исход
решает политика фазы, в записи `applied:false, partial:true`, в логе WARN. Аудит и архив хранят
оригинал — снятое уехало в обменник до подмены.

## Тело собственного отказа

`deny` с секцией `rewrite` на фазе запроса: модуль отдаёт объект телом ответа с кодом записи
`response`, до апстрима не доходя. Так форма входа и виджет капчи приходят на том же URI — без
редиректа, без прокси-локации и без записи каталога со страницей.

```json
{
  "v": 2,
  "rid": "480000013b000000",
  "inspector": "auth",
  "verdict": "deny",
  "reason": { "code": "AUTH_NO_SESSION", "scope": "session" },
  "response": { "name": "auth_required" },
  "rewrite": {
    "body": { "key": "nginx-1:480000013b000000:req:form", "size": 4096, "sha256": "…" },
    "content_type": "text/html; charset=utf-8"
  },
  "cookies": [
    { "name": "waf_ticket", "value": "eyJ0IjoxNzU3…", "path": "/", "max_age": 300 }
  ]
}
```

Билет едет и на отказе: POST входа без nonce не примут. С провода у cookie принимаются только
`name`, `value`, `path` и `max_age`; `secure`, `http_only`, `same_site` разбираются строго, но затем
отбрасываются — их назначает `waf_cookie_defaults` маршрута, а `domain` отбрасывается всегда, cookie
остаётся host-only.

Объект не поднялся — обычный отказ страницей записи `response` и строка WARN. Форму не удалось
собрать вовсе — калитка падает в редирект на неё, как профиль без `inline`.

## Редирект

```json
{
  "v": 2,
  "rid": "480000013b000000",
  "inspector": "captcha",
  "verdict": "redirect",
  "reason": { "code": "CAPTCHA_REQUIRED", "scope": "session", "retry": 30 },
  "redirect": { "url": "/waf/captcha?rd=%2Fapi%2Forders", "status": 303 },
  "cookies": [
    { "name": "waf_chal", "value": "eyJ0IjoxNzU1…", "path": "/", "max_age": 300 }
  ]
}
```

Единственное место, где с провода принимается адрес, а не имя, — и потому проверяется отдельно:
только печатный ASCII, длина по `waf_header_value_max`, без обратного слеша, без формы `//host/path`,
без `userinfo`, схема `http` или `https`, и совпадение хотя бы с одним шаблоном `waf_redirect_allow`
маршрута. Пустой список — редиректы здесь запрещены вовсе.

Не прошло — это битый ответ, а не отказ: он отбрасывается целиком, волна продолжает ждать, исход
определяет `waf_deadline`. Коды только `302`, `303`, `307`; умолчание `303`. На фазе ответа и на
кадрах вердикт запрещён.

## Продолжение

Секция `continue` — это ответ инспектора «я не выбросил транзакцию, спрашивайте меня же на поздней
фазе». Одному инспектору дешевле доиграть уже начатую работу (движок правил держит разобранный
запрос, счёт фаз 1–2, состояние сессии), чем восстанавливать контекст с нуля на фазе ответа.

```json
{
  "v": 2, "rid": "480000013b000000", "inspector": "modsec",
  "verdict": "score", "score": 15,
  "continue": { "subject": "waf.req.modsec.i.7f3a91", "ttl_ms": 30000 }
}
```

| Поле | Что это |
| --- | --- |
| `subject` | Личный subject экземпляра: куда публиковать сообщение поздней фазы, чтобы попасть именно в тот процесс, который держит состояние |
| `ttl_ms` | Сколько миллисекунд экземпляр обещает его держать. Истёк — состояния может не быть |

Договорённость двусторонняя, и начинает её модуль. На маршруте с `keep=on` у `waf_inspect` фазы
запроса в вопросе едет `resume: { "want": true, "token": "…" }` — только увидев `want`, инспектор
вправе держать транзакцию: без него он обязан выбросить её, ответив, иначе маршруты, которым
липкость не нужна, платили бы памятью за каждый запрос. На поздней фазе модуль публикует в
`continue.subject` и возвращает тот же ключ с требованием маршрута:
`resume: { "token": "…", "require": false }`.

**Ключа в реплае нет намеренно.** Его назвал модуль в самом вопросе — это `ray`, один на запрос и
переживающий фазы, в отличие от `rid`, который кодирует слот ожидания и берётся заново на каждую
волну. Ключ, существующий только в ответе, нельзя было бы ни использовать, ни отозвать, если ответ
не дошёл. Адрес — единственное, чего модуль знать не может: какой экземпляр очереди взял сообщение,
известно только этому экземпляру.

Воспользуется модуль продолжением лишь при `resume=prefer|require` на поздней фазе. При `prefer`
исчезнувший экземпляр не беда: соединение с шиной поднято с `no_responders`, публикация в мёртвый
subject возвращает 503 немедленно, и сообщение тут же уходит в групповой subject — инспектор
переигрывает транзакцию и отвечает тем же вердиктом меньшей полноты. `require` — сознательный отказ
от этого: там правила фазы ответа смотрят на то, чего в переигранной транзакции нет, и отказ честнее
проверки, которая молча не сработает.

Продолжение чаще не понадобится, чем понадобится — отказал сосед на волне раньше, фаза ответа не
побежала (204, 304, апгрейд), клиент оборвался. Тогда в конце запроса модуль публикует освобождение
на `<subject инспектора>.release`, в один конец и без ответа:

```json
{ "v": 2, "rid": "480000013b000000", "inspector": "modsec", "phase": "response",
  "release": { "token": "7b21c0a8-f3e1-4d5a-8c2e-91b04f6a1d03", "reason": "deny" } }
```

Тема общая, а не личная: когда волна замкнулась на чужом `deny`, наш ответ пришёл в закрытый слот и
был отброшен вместе с `continue` — личного адреса модуль в этом случае не знает вовсе. `reason`
(`deny` либо `skip`) ни на что не влияет и нужен затем, чтобы в логе инспектора было видно, почему
липкость на маршруте не срабатывает. Срок `ttl_ms` при этом остаётся страховкой на случай, когда
освобождение не доедет.

Инвариант: **липкость — оптимизация, а не канал данных.** Сообщение поздней фазы одинаково с
продолжением и без него, меняется только subject; пару `keep=`/`resume=` можно включить позже и
выключить в любой момент. Что `keep=on` не останется без потребителя, проверяет `nginx -t` — пара
сверяется по эффективным маршрутам в обе стороны.

## Кадр

```json
{
  "v": 2,
  "rid": "480000013b000000",
  "inspector": "counter",
  "verdict": "allow",
  "reason": { "code": "COUNTER_MEASURED" },
  "cache": false,
  "actions": [
    { "to": "modsec", "do": "threshold", "apply": "conn", "value": 30, "code": "WS_FLOOD" }
  ]
}
```

`cache: false` — вердикт зависит не от содержимого кадра (корзины, сессия, время), и повторять его
по хешу нельзя: `waf_frame_cache` такой кадр не запоминает. Счётчик судит по корзинам и шлёт `false`
на кадрах всегда; отсутствие поля равнозначно `true`.

Допустимы `allow`, `score` и `deny`. Секция `headers` на кадре не применяется, подмена нагрузки — та
же `rewrite` с ключом `…:frm:<суффикс>`, одна на кадр.

## Просьбы соседям

От вердикта не зависят и чаще всего едут с `allow` — это основной случай канала:

```json
{
  "v": 2,
  "rid": "480000013b000000",
  "inspector": "ip",
  "verdict": "allow",
  "reason": { "code": "IP_OK" },
  "actions": [
    { "to": "captcha", "do": "challenge", "apply": "request", "code": "IP_GREYLIST" }
  ]
}
```

Модуль просьбу не исполняет — кроме тех, чей адресат он сам: режим вызова соседа, журнал и архив
запроса, маркер записи. Остальное он проверяет по форме, ограничивает числом и размером
(`waf_actions_max`, `waf_action_max`) и переносит в `prior` следующей волны, где поля `to` уже нет:
адресат тот, кто читает. Словарь глаголов, осей и параметров —
[inspector-actions.md](../inspector-actions.md).

## Служебные ответы

Отвечать обязан и тот, кто не разобрал вопрос: молчание модуль не отличит от перегрузки, и обойдётся
оно в дедлайн волны. Поэтому даже нераспарсенное сообщение получает ответ, и ради него из мусора
вынимается `rid`.

```json
{"v": 2, "rid": "480000013b000000", "inspector": "ip", "verdict": "error", "reason": {"code": "IP_MALFORMED_REQUEST"}}
{"v": 2, "rid": "480000013b000000", "inspector": "ip", "verdict": "error", "reason": {"code": "IP_QUEUE_LIMIT"}}
{"v": 2, "rid": "480000013b000000", "inspector": "ip", "verdict": "error", "reason": {"code": "IP_DEADLINE_EXCEEDED"}}
```

Вердикт у всех трёх один — `error`, «проверить не смог», и это единственное, что инспектор о своём
сбое говорит. Сторону выбирает маршрут: `waf_exception <фаза> inspector pass|deny`. Раньше каждый
инспектор решал сам и по-разному — у адреса переполненная очередь означала пропуск, а вышедший
дедлайн отказ; калитка и счётчик отвечали `allow` на любой сброс. Все эти половины были догадкой о
том, что важнее на конкретном маршруте.

## Что отбраковывает ответ целиком

Не «поле проигнорировано», а весь реплай отброшен, и волна дальше ждёт молчания:

- `rid` не совпал, `inspector` вне маски волны, незнакомый `v`;
- `score` дробный, отрицательный или больше ста;
- запрещённое имя заголовка, CR/LF/NUL в имени или значении, длина сверх `waf_header_value_max`;
- `redirect` без адреса либо не прошедший проверку цели;
- незнакомый глагол или ось в `actions`, повод вне `[A-Z][A-Z0-9_]*`, `delta` вне −1000…1000,
  `value` вне 0…1000;
- битая форма `args`, `rewrite.body` без `key` или без `size`;
- пятая запись в `sessions`, строка сверх своего предела или с управляющим символом;
- размер ответа сверх `waf_reply_max`.

Молчаливо гасятся только три публичных поля `reason` — `scope`, `subject`, `retry`: ошибка в
объяснении не должна отменять само решение.
