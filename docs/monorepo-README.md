# nginx-waf

Модуль nginx, который согласует решение по каждому HTTP-запросу и каждому ответу с внешними
сервисами-инспекторами через шину сообщений и пропускает трафик только при их согласии.

Модуль намеренно не содержит логики детекта. Он занимается транспортом, синхронизацией, буферами,
дедлайнами, политиками отказа и применением вердиктов. Всё, что связано с анализом, живёт в
отдельных сервисах, которые можно писать на любом языке, разворачивать на отдельных машинах и
обновлять независимо от nginx.

## Как это выглядит

```nginx
load_module modules/ngx_http_waf_module.so;

http {
    waf_bus nats://nats-1:4222,nats-2:4222;

    waf_store driver=redis url=redis://redis-1:6379 ttl=30s max=8m;

    waf_redirect_allow /waf/captcha;

    waf_inspector ip        subject=waf.req.ip     timeout=5ms   needs=none;
    waf_inspector sqli      subject=waf.req.sqli   timeout=15ms  after=ip
                            needs=headers,args,body body=preview=8k;
    waf_inspector repu      subject=waf.req.repu   timeout=10ms  after=ip
                            weight=0.5;
    waf_inspector challenge subject=waf.req.chal   timeout=10ms  needs=headers
                            after=sqli,repu weight=0;
    waf_inspector dlp       subject=waf.rsp.dlp    timeout=20ms
                            needs=headers,body body=preview=64k;

    server {
        listen 443 ssl;

        location / {
            waf on;
            waf_request_inspectors  ip sqli repu challenge;
            waf_response_inspectors dlp;
            waf_capture             request headers args body;
            waf_deadline            25ms block;
            waf_score_deny          100;

            proxy_pass http://app;
        }

        location = /healthz { waf off; }
    }
}
```

## Ключевые понятия

**Инспектор** — внешний сервис, который получает описание запроса или ответа и возвращает вердикт.
Инспекторы объявляются по имени в конфигурации nginx; каждому имени при загрузке конфига выдаётся
индекс бита, поэтому проверка «все ответили» стоит одно целочисленное сравнение.

**Вердикт** — одно из четырёх значений: `allow`, `score`, `redirect`, `deny`. Вместе с вердиктом
инспектор может прислать переопределение заголовков и набор cookie, вместе с `deny` — символьное имя
страницы отказа, вместе с `redirect` — адрес, куда вести клиента.

**Счёт** — то, чем инспектор отвечает, когда нашёл признак, но не доказательство: число от 0 до 100.
Модуль складывает вклады всех инспекторов с настраиваемыми весами и сравнивает сумму с порогом
маршрута `waf_score_deny`. Безоговорочная блокировка остаётся доступной — `deny` порога не смотрит.
Смысл разделения в том, что политика живёт в конфигурации nginx и меняется на отдельном location без
выкатки сервисов детекта, а инспектор отвечает только за качество своей оценки.

**Челлендж** — единственное решение, которое модуль не принимает. Из накопленного счёта он выводит
только отказ; требование доказать, что клиент человек, приходит готовым вердиктом `redirect` от
сервиса, который челлендж и ведёт: только тот знает, доступна ли проверка, сколько попыток клиент
потратил и на какой адрес его вести. Модуль сверяет присланный адрес с `waf_redirect_allow` маршрута —
это его единственная роль здесь, и она же граница между инспектором и открытым редиректом.

**Волна** — группа инспекторов, исполняемых параллельно. Волны вычисляются из графа зависимостей
`after=` топологической сортировкой при загрузке конфига. Следующая волна публикуется, только если
предыдущая никого не заблокировала и счёт не дотянул до порога. Это позволяет поставить дешёвую
проверку адреса перед дорогим разбором тела и не дать заддосить дорогие инспекторы, а сервис
челленджа — за скорящими, чтобы он решал по полной сумме.

**Обменник** — подключаемый драйвер, один на контур (`waf_store`). Тело, заголовки и строка запроса
кладутся туда, а в сообщении едут только локаторы одной формы. Что снимать ради инспекторов, решает
`waf_capture`, кому это показывать — `needs=` инспектора. Драйверы встроенные: `none`, `inline`,
`redis`. Интерфейс открыт для собственных.

**Архив** — то, что переживает запрос. `waf_archive request` называет объекты, которые модуль не
удаляет после вердикта, и срок их хранения; агент перекладывает их в S3, подменяет локаторы в записи
аудита и чистит обменник сам. В горячем пути этого нет ни одним вызовом. От `waf_capture` архив не
зависит: названное в нём снимается независимо от того, нужно ли это хоть одному инспектору.

**Трансформация тела** — необязательный внешний сервис, который преобразует тело перед размещением.
Основное применение — маскирование, чтобы приватные данные не попадали в контур WAF вообще. Приложение
при этом всегда получает оригинал.

**Кадр** — единица инспекции для трафика без завершённого тела: сообщение WebSocket, length-prefixed
message gRPC, событие SSE. Вердикт выносится по каждому кадру; режим `gate` удерживает кадр до вердикта,
`monitor` закрывает соединение по факту нарушения.

**Аудит** — событие с настраиваемым набором полей, публикуемое в поток JetStream по принципу
fire-and-forget и забираемое ClickHouse через родной движок NATS. Аудит никогда не входит в набор
ожидания и никогда не задерживает запрос.

## Что этот продукт делает и чего не делает

Делает: перехват запроса и ответа, синхронный опрос набора инспекторов с зависимостями и
дедлайнами, сведение их оценок в решение по настраиваемому на маршруте порогу, применение вердиктов
вплоть до подмены кода, заголовков, cookie и страницы, управление доступностью тела для инспекторов,
предсказуемое поведение при отказах, структурированный аудит.

Не делает: не содержит правил детекта, не хранит состояние сессий, не заменяет rate limiting самого
nginx, не выполняет ретраи к приложению, не откатывает побочные эффекты. Блокировка на фазе ответа
предотвращает утечку данных, но не отменяет то, что приложение уже сделало. Не понимает семантику
двоичных протоколов без схемы: кадрирование gRPC разбирается, но смысл сообщений остаётся на инспекторе.

## Требования

- nginx 1.22 или новее, собранный с поддержкой динамических модулей. Модуль подключается через
  `load_module`, замена дистрибутива nginx не требуется.
- Кластер NATS с включённым JetStream: core NATS обслуживает горячий путь, JetStream — аудит,
  датасеты локального слоя и манифест desired-конфигурации nginx.
- Если инспекторам нужно тело или сырые заголовки: Redis. Если нужен ещё и архив под разбор
  инцидентов: S3-совместимое хранилище, три бакета, доступ только у агента.
- Для раскатки конфига из контроллера: бакет S3 и/или Redis под конфигурационный store (не тот
  префикс и не тот TTL, что у тел запроса), Secret с ключом контура на нодах.
- Опционально, для аудита: ClickHouse 25.3 или новее, если планируется использовать колонку типа
  `JSON` для открытых полей.
