# Сценарии настройки: куда что кладётся

Проверка панели вопросами оператора, а не списком директив. Каждый вопрос —
реальная задача; ответ — место в интерфейсе либо честное «этого нет».

Директивы — [docs/directives/list](../directives/list). Разбор слоёв —
[config-ux.md](config-ux.md).

## Граница слоёв, ещё раз

| Слой | Что решает | Директивы |
| --- | --- | --- |
| `http` | что в контуре **есть** | `waf_bus`, `waf_store`, `waf_shm_zone`, `waf_inspector`, `waf_local_dataset`, `waf_deny_response`, `log_format`, `waf_log_format`, ядро nginx |
| `server` | что делать с запросами **этого хоста** | `waf on`, `waf_inspect`, `waf_local_check`, `waf_local_rate`, `waf_capture`, `waf_archive`, `waf_preview`, бюджеты, счёт, `access_log` |
| `location` | чем **этот путь** отличается от хоста | то же самое, переопределением |

Сервер набор инспекторов не наследует: в `http` его нет. «Нет строки фазы» на
сервере значит «фаза не бежит», а не «взять сверху». Путь наследует — от сервера.

## Списки

**Объявить список для банов по адресу, состав с контроллера.**
`http` → Списки → создать: `type=ipv4`, режим `active`, `limit`, `ttl`.
Печатается `waf_local_dataset blocklist type=cidr limit=1000000 ttl=5m active`.
Тема — `waf.sets.<имя>` у keeper; своей у набора нет.

**Объявить список user-agent'ов.** То же, `type=string`: сравнение байт в байт.

**Объявить список, который живёт в конфиге.** Режим `internal`. `ttl=` у него
нет — задать это `nginx -t`. Смена состава требует reload; у `active` не требует.

**Откуда взять начальное состояние.** Сейчас — только пустым, состав потом в
«Данных». **Пробел:** нельзя сказать «возьми состав из вот этого набора».
Нужен выбор источника при создании: пусто / копия существующего набора /
загрузка файлом.

**Указать ttl.** Поле `ttl` у режима `active`. Это срок живых записей —
автобана от rate и точечного `add`, — а не срок снапшота.

## Инспекторы

**Объявить десять имён на одном сервисе.** `http` → Инспекторы → «Объявить
инспектора»: имя своё, `subject` выбирается из уже заведённых. Ровно это и есть
`allow_ip` / `strict_ip` — один процесс, разные профили.

**Выбрать профиль.** Поле `profile=` — поиск по профилям правил и профилям
адреса, сгруппированным; своё имя вводится руками, потому что «какие профили
есть, решает инспектор».

**Сменить профиль валидатора на одном пути.** Не переключателем на пути:
`profile=` — опция реестра. Объявить второе имя с другим профилем и вызвать
его на этом пути. Так же устроен пример `/strict/` в документации.

**Предохранитель.** Одна фраза: «открыть при 50% таймаутов за 10s, проба раз в
5s», редактируется на месте. Три колонки `threshold= window= probe=` с голыми
`10s` / `5s` не читались — значения были видны, правило нет.

**Назначить, кого звать.** Сервер → Параметры защиты: `wave=`, `timeout=`,
`weight=`, `mode=`. Волны рисуются по явному номеру.

**Переопределить набор на пути.** Путь → Параметры защиты → «переопределить».
`none` гасит фазу целиком.

## Локальный слой

**Белый список на сервере.** Сервер → `waf_local_check`: набор, переменная,
`action=allow`. Стоит выше `block` — порядок объявления и есть приоритет.

**Пропустить инспекторов, если адрес в списке.** Там же: `action=allow` —
мимо всего, включая волны. `action=wave` — мимо остальных локальных проверок,
но инспекторы бегут.

**Рейт-лимит.** Сервер → `waf_local_rate`: ключ, `rate=`, `burst=`,
`response=`. Автобан — `list=` плюс `ttl=`; `action=pass` вместе с `list=`
отвергается.

**Что сравнивать.** Готовые переменные плюс разбор по имени: заголовок,
cookie, аргумент. `X-Api-Key` → `$http_x_api_key`. Тип набора решает, что
предлагать: у `cidr` только адрес.

## Страницы отказа

**Загрузили страницу — как объявить.** Две сущности, и связь между ними сейчас
нигде не показана:

```
Страницы (response_pages)     HTML, который отдаётся
      ↑ по имени
location @waf_deny            именованный путь сервера, ssi on
      ↑ page=@waf_deny
waf_deny_response blocked     status=403 page=@waf_deny
      ↑ по имени
waf_deny_response_default / waf_score_deny response= / check response=
```

`page=` принимает **только** `@имя`: модуль сам на страницу не ходит, он
отдаёт статус, а страницу подставляет nginx через `error_page`.

**Пробел:** `page=` — свободный текст, а должен быть выбор из именованных
путей; и на карточке не видно, что без `error_page` на сервере страница не
отдастся.

**Своя запись на пути.** Путь → `waf_deny_response_default`, либо
`response=` у конкретной проверки.

## Снимок, архив, превью

**Определить, что снимаем.** Сервер (и путь) → `waf_capture`. Не `http`: это
решение по трафику хоста.

**Скрыть заголовок под маску.** `waf_capture request headers mask=<имя>` —
инспекторы видят маску. `deny=` — не видят вовсе.

**Отправить в S3.** `waf_archive` на сервере или пути: что агент увезёт после
вердикта.

**Другая запись аудита на пути.** `waf_preview` на пути: свой срез.

**Скрыл на capture, но в архиве хочу оригинал.** `reload`: `waf_archive
request reload headers` кладёт в Redis оригинал, инспекторы его не видят.
То же у превью.

**Пробел:** все три — свободный текст. Хвост директивы разбирается только
`nginx -t` на ноде. Нужна таблица «объект × ось»:

| Объект | Снимать | Маска | В архив | В превью |
| --- | --- | --- | --- | --- |
| headers | `64k` | `mask=cookie` | `reload`, весь | `30k/2k` |
| args | весь | — | — | `8k/1k` |
| body | `4k` | — | `reload body=capture` | — |

Проверки размеров (`> waf_body_limit`, `> client_max_body_size`, объект не из
capture без `reload`) переносятся в форму.

## Логи

**Логи хоста.** Сервер → `access_log` списком приёмников, `error_log` с
уровнем. Формат выбирается из каталога.
**Заглушить на пути.** Путь → `access_log` → «снять» = `access_log off`.
**Формат.** `http` → Форматы: `log_format` для nginx, `waf_log_format` для
записи аудита.

---

## Ядро nginx

**Включить gzip на пути.** **Пробела нет в nginx, есть у нас:** `gzip` в
модели только на `http`, хотя директива работает и в `server`, и в `location`.
То же у `client_max_body_size` — он есть везде, а вот `gzip_types`,
`gzip_comp_level` на сервере и пути отсутствуют.

## Что делать со структурой

«Каталоги» отдельным пунктом меню — ошибка: это всё опции `http {}`. Их надо
собрать на одной странице и разложить по частоте, а не по таблице в базе:

| Ярус | Что | Когда трогают |
| --- | --- | --- |
| Сразу видно | инспекторы, списки, страницы отказа | при заведении контура и потом постоянно |
| Ниже | шина, обменник, зона, форматы логов | один раз, при развёртывании |
| Под «показать» | скелет файла, буферы, keepalive, hash-таблицы, resolver | почти никогда |

## Пробелы: закрыты

1. **Инициализация списка** — при создании выбирается набор-источник того же
   типа, копируются живые записи в пределах `limit`
   ([`DatasetRepo.copyAddresses`](../../controller/src/datasets.ts)).
2. **`page=`** — выбор из каталога страниц; подпись объясняет, что модуль сам
   на страницу не ходит, а уводит nginx через `error_page`.
3. **`capture` / `archive` / `preview`** — таблица «объект × ось»
   ([`CaptureTable.tsx`](../../controller/ux/src/config/CaptureTable.tsx)),
   грамматика хвостов в одном месте
   ([`directive-tail.ts`](../../controller/ux/src/config/directive-tail.ts)),
   `mask=` / `deny=` / `reload` полями, проверки размеров -- предупреждением в
   форме, а не отказом `nginx -t` на ноде.
4. **`gzip*` на сервере и пути** — в модели, в трёх эмиттерах, в наследовании,
   в форме (`src/compile/nginx-gzip.test.ts`).
5. **Каталоги** — секциями на странице `http`, отдельной страницы нет.
