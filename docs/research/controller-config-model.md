# Модель конфигурации в контроллере

Как хранить серверы, пути и настройки nginx+WAF в Postgres, чтобы из дерева
собрать шаблон, а не наоборот — править текст конфига и парсить его обратно.

Код на сейчас: `controller/schema/migrations/001_init.sql`, `controller/src/model/`.
Раскатка готового шаблона на флот — уже спецификация,
[config-distribution.md](../config-distribution.md). Этот текст — про то, из чего
шаблон берётся, и он ещё не принят.

## Коротко

Контроллер хранит дерево с UUID на каждой сущности. Общие опции `http {}` не
живут одним jsonb: каталоги — таблицы, http-only скаляры — `waf_http`,
наследуемое — тот же `WafRouteSettings`, что на сервере и пути. Слияние вниз —
замена ключа, пустой массив снимает родительское. Порты и сертификаты
привязываются к серверу, апстрим — к пространству, путь на него ссылается.
PEM в базе нет.

Этого хватает, чтобы описать контур уровня `deploy/nginx.conf`. Не хватает
поколения/`send`, узлов флота, `reuseport`, dual-cert, и того, что
`waf_node_id` нельзя класть в общий шаблон. `raw` на пространстве, сервере
и пути — выход для всего, что сознательно не моделируем.

## Принятые на сейчас решения

Не спецификация продукта, а договорённость, из которой писалась схема. Менять
можно, но тогда править SQL и типы вместе.

**UUID везде.** В API, в FK и в `store:<uuid>` одна строка. Автоинкремент не
переживёт обмен объектом между контурами.

**Источник — дерево, пока не включён `raw`.** Оператор не редактирует `nginx.conf`,
пока флаг выключен. Генератор печатает шаблон из Postgres. `raw` на пространстве,
сервере или пути заменяет внутренности этого блока текстом; скелет (listen,
`server_name`, match пути) остаётся. PEM в raw запрещён.

**Три места для опций `http {}`, не одно.**

1. Таблицы-каталоги: инспектор, набор, ответ отказа, хранилище тела, формат
   лога, апстрим, порт, сертификат. Есть имя, на них ссылаются.
2. `http_spaces.waf_http`: шина, зона, пределы сообщения. Только `http`, на
   сервер не наследуется.
3. `http_spaces.waf`: значения по умолчанию контура. Документ
   `WafRouteSettings`. Ниже — разреженный оверлей того же типа.

Ядро nginx (`keepalive`, `resolver`) — поле `nginx`, отдельно от модуля.

**Слияние — замена.** Ключа нет — взять у родителя. Ключ есть — целиком то, что
записано. Массивы не конкатенируются: три проверки на сервере и одна на пути —
на пути одна. Пустой массив — снять. В модуле `waf_local_check none` ещё нет;
модель это умеет, генератор либо научится, либо откажется печатать такой путь.

**Порт не слушает сам.** Каталог адресов плюс привязка к серверу. Один порт на
два `server_name` — виртуальные хосты. `ssl`, `http2`, `default_server` живут на
привязке: в nginx они стоят на `listen`.

**Сертификат — к серверу, не к порту.** SNI выбирает `server {}`. В Postgres —
имя, SAN, срок и UUID объектов `store_objects`. Тело сертификата — ciphertext в
той же базе, контроллер его не открывает.

**Апстрим принадлежит пространству.** Путь ссылается uuid-ом, не именем: пул
можно переименовать, не трогая location.

**Имена в оверлее, uuid в связях.** `waf_inspect` и
`waf_local_check` в nginx — имена, и в `WafRouteSettings` тоже. Апстрим и
сертификат выбираются целиком — там uuid, в шаблон генератор подставляет имя.

## Что схема уже покрывает

Хватает, чтобы собрать боевой виртуальный хост: listen, TLS, `proxy_pass` в
именованный пул, набор инспекторов, локальные проверки и лимиты, страницу
отказа из каталога, `waf off` на служебном пути через `enabled: false` в оверлее.

| Сущность | Зачем |
| --- | --- |
| `http_spaces` | Один блок `http {}` на контур; всегда есть `default`; `raw` / `raw_nginx` |
| `inspectors`, `deny_responses`, `body_stores`, `log_formats` | Каталоги модуля, в пространстве |
| `datasets` | Каталог `waf_local_dataset` (uuid, имя, subject, type, max) |
| `dataset_addresses` | Адреса набора: uuid, dataset_id, address |
| `upstreams` + `upstream_peers` | Пул и его члены, вес, backup, down |
| `ports` | Каталог listen-адресов |
| `certificates` | Метаданные TLS, ссылки на `store_objects` |
| `store_objects` | Ciphertext файлов шаблона: uuid, type, metadata, blob |
| `rule_files` | Мини-набор SecLang в пространстве: один `text_raw` |
| `rule_sets` + `rule_set_files` | Профиль: упорядоченный список файлов, имя уходит в `profile=` реестра |
| `servers` | `server_name` + оверлеи + `raw` / `raw_nginx` |
| `server_ports` | `listen … ssl http2`, ровно один `default_server` на порт |
| `server_certificates` | kind: `server` / `client_ca` / `trusted` |
| `locations` | match как у nginx, handler, апстрим, оверлеи + `raw` / `raw_nginx` |

Match пути: `prefix`, `exact`, `regex`, `regex_i`, `named`. Handler: `proxy`,
`static`, `return`, `named`, `metrics`. Порядок regex — поле `position`.

## Чего не хватает, чтобы этим пользоваться

Схема описывает статическое дерево. Раскатки, узлов и нескольких забытых
свойств nginx в ней нет. Без них генератор либо напечатает невалидный край,
либо не сможет сделать `send`.

### Узел и поколение

`waf_node_id` сейчас торчит в `WafHttpSettings`. Это ошибка: идентификатор
обязан быть уникален на флот, общий шаблон с одним `node_id` на все машины
склеит инбоксы. В шаблоне должен стоять плейсхолдер, который подставляет агент
(имя хоста, env), либо поле живёт в карточке узла, не в пространстве.

То же про `events { worker_connections }`, `worker_processes`, путь `error_log`
на диске ноды. Это свойства процесса на железе, не виртуального хоста. Их нет в
схеме, и класть в `http_spaces` нельзя.

Нет таблицы узлов флота и нет поколения: черновик ≠ `send`. Манифест из
[config-distribution.md](../config-distribution.md) из этого дерева ещё не
собирается. Объекты store уже в Postgres: агент заберёт ciphertext
`GET /api/<scope_uuid>/store/<uuid>/blob`.

### Служебные пути как тип, не как хак

В `deploy/nginx.conf` есть три пути, которые не «ещё один location с оверлеем»:

- `/healthz` — `waf off`, без апстрима, эталон healthcheck;
- `/waf/captcha` — `waf off`, цель редиректа, обязана открываться при мёртвом
  инспекторе;
- `/waf/metrics` — `waf_status`, закрыт `allow`/`deny`.

Сейчас роль пути (`healthz` / `challenge` / `metrics` / `deny_page`) и
`internal` стоят в `NginxLocationSettings`. UX не предлагает инспекторов на
captcha. Связь `deny_responses.spec.page` → location всё ещё строка, не uuid.
Разъедется.

### TLS, который схема упрощает

`unique (server_id, kind)` на `server_certificates` запрещает пару RSA+ECDSA на
одном сервере: оба kind=`server`. Dual-cert в nginx — две директивы
`ssl_certificate` подряд. Либо снимать уникальность, либо kind становится
`server` + алгоритм.

Нет listen-флагов `reuseport`, `backlog`, `bind`, unix-сокета, `quic` / HTTP/3.
Для первого края не нужно; для боевого — `reuseport` почти наверняка понадобится.

Редирект HTTP→HTTPS — поле `httpsRedirect` на сервере, не сборка из
`return 301` на `/`.

### Адрес клиента за балансировщиком

Локальный лимит и `waf_local_check` по `$binary_remote_addr` без `real_ip`
считают адрес HAProxy, не клиента. В `NginxHttpSettings` это уже есть:
`realIpFrom` / `realIpHeader` / `realIpRecursive`. Без них выкатить контур
за балансировщиком и включить лимит по IP нельзя.

### Прокси, без которого апстрим бесполезен

Пресет `proxyHeaders: "standard" | "websocket" | "none" | "custom"` и
`proxyHttpVersion` стоят на http (дефолт контура) и на пути. `standard` —
Host / X-Real-IP / X-Forwarded-For / X-Forwarded-Proto; `websocket` —
плюс Upgrade / Connection; `custom` — только `proxySetHeaders`.

Нет `proxy_next_upstream`, TLS к апстриму (`proxy_ssl_*`), `grpc_pass`.
gRPC — когда до него дойдёт модуль.

`handler: proxy` предполагает именованный upstream. Прямой `proxy_pass http://10.0.0.5:8080`
и unix-сокет не выражены. Сначала запретить: иначе плодятся обходы каталога
пулов. Если понадобится — отдельный kind, не строка в `upstream_uri`.

### Имена против uuid в одном документе

`inspectors.after` в SQL — массив uuid, в оверлее инспекторы — имена.
`LocalCheck.dataset` — имя. Переименование набора правит все оверлеи, либо
генератор резолвит uuid→имя при печати, а в jsonb лежат uuid. Второе лучше,
сейчас сделано первое (как в nginx). Это надо выбрать один раз до API, иначе UX
начнёт писать то имена, то id.

### Что сознательно не моделируем — это `raw`

Не отдельные jsonb-поля и не «сниппет в конец файла». Флаг `raw` на том
уровне, где мини-язык или подсистема нужны:

- `map`, `geo`, `split_clients`, `if`, вложенные `location`;
- штатный `limit_req` / `limit_conn` (есть `waf_local_rate`);
- `proxy_cache_path` / кэш, зеркалирование, `auth_request`;
- lua / perl / njs, произвольный `include`;
- кадры / `waf_frame_*` — этап 12, пока raw;
- трансформеры тела — этап 11, каталог как у `body_stores`, когда дойдёт.

## Каких параметров должно хватить

Не всех директив nginx — того набора, без которого край из контроллера
неотличим от осмысленного `nginx.conf` с модулем. Ниже — инвентарь: что уже в
типах, что добавить до первой генерации, что подождёт.

### Уже в модели — хватит для WAF-маршрута

Наследуемое (`WafRouteSettings`): включение, наборы инспекторов, режимы и
профили, дедлайны, политики отказа, тело, скоринг, каталог отказа, редирект
allow, cookie defaults, локальные проверки и лимиты, аудит, debug-заголовок.

Http-only модуля: шина, зона, пределы ответа, inflight, holds тела.

Ядро nginx на http (`NginxHttpSettings`): sendfile / tcp_nopush / nodelay,
keepalive (timeout / requests / time), клиентские таймауты и буферы,
`large_client_header_buffers`, `default_type`, `underscores_in_headers`,
`ignore_invalid_headers`, `merge_slashes`, `server_tokens`, hash bucket/max
для `server_names` и `types` (иначе nginx не стартует), resolver, real_ip,
lingering / `reset_timedout_connection`, gzip, дефолты ssl сессии, пресет
прокси, глобальные `add_header`.

Сервер: `client_max_body_size`, root, charset, `httpsRedirect`, ssl override,
`ssl_verify_client`.

Путь: root/alias/try_files, allow/deny, `internal`, роль
(`healthz` / `challenge` / `metrics` / `deny_page`), таймауты прокси,
пресет / custom заголовков.

Апстрим: метод, hash key, keepalive, вес, backup, down, fail_timeout.

### Добавить до первой печати шаблона

Не http-скаляры — то, без чего генератор либо невалиден, либо не умеет `send`.

| Параметр | Куда | Зачем |
| --- | --- | --- |
| `reuseport` | привязка порта | несколько воркеров на одном listen |
| `ssl_certificate` dual (RSA+ECDSA) | снять unique kind | иначе второй сертификат не повесить |
| `waf_node_id` убрать из пространства | узел / агент | иначе общий шаблон склеивает инбоксы |
| черновик и `rev` поколения | таблицы | иначе нечего класть в KV |

### Подождёт первого боевого контура

HTTP/3 (`listen … quic`), unix-listen, `proxy_ssl_*`, `grpc_pass`, OCSP,
`ssl_dhparam`, очередь/sticky апстрима — либо позже отдельным полем, либо raw.

`error_log` / `access_log` как путь на диске — свойство ноды, в шаблоне либо
плейсхолдер агента, либо не трогаем (агент держит свой `nginx.conf` обёрткой
вокруг сгенерированного `http {}`). Это ещё не решено.

## Как из этого печатать

Генератор идёт сверху вниз. Если у пространства `raw` — печатается `http {`
и `raw_nginx`, каталоги и серверы из таблиц не едут. Иначе: каталоги,
`upstream {}`, затем каждый сервер. Если у сервера `raw` — `listen`,
`server_name`, `ssl_*` из сертификатов (`store:<uuid>`), затем `raw_nginx`;
пути не печатаются. Иначе оверлей после `resolveRoute(http, server, {})` и
пути по `position`; у пути с `raw` — только match/path и текст.

Агент по-прежнему единственный, кто подставляет store в путь на диске и делает
`nginx -t` / `reload`. Контроллер PEM не видит.

## Открытые вопросы

1. `waf_node_id` и `worker_processes` — карточка узла в контроллере или только
   окружение агента? Контроллеру полезно знать состав флота для сходимости,
   агенту — не ждать контроллер, чтобы просто подняться.
2. Оверлей хранит имена или uuid? Имена совпадают с nginx и читаемы в jsonb;
   uuid переживают переименование. Смешивать нельзя.
3. Пустой `localChecks: []` — учить модуль `none` или генератор вставляет
   фиктивное правило, которое никогда не бьёт? Фиктивное правило — ложь в
   конфиге. Лучше директива в модуле.
4. Dual-cert: массив сертификатов kind=`server` или отдельные kind?
5. Обёртка ноды: контроллер печатает весь `nginx.conf` или только `http {}`, а
   `events` / `pid` / `error_log` остаются файлом агента?
6. Прямой `proxy_pass` на адрес без upstream — запретить навсегда или kind
   позже?
7. Связь `deny_responses.page` → named location: строка как в nginx или uuid
   пути?

Пока эти семь не закрыты, API записи дерева делать рано: иначе придётся
мигрировать jsonb у живых серверов.
