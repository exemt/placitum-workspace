# audit — что доезжает до шины и дальше

Три прогона: [локаторы после архивации](#локаторы), [превью запроса](#превью) и
[усечённое тело](#усечённое-тело). Все из nats-box, а не из nginx: клиента шины
в контейнере nginx нет.

## Локаторы

Что доезжает до `WAF_AUDIT` с маршрута `/body/archive/`: агент забирает
удержанные модулем объекты из Redis, кладёт в MinIO и подменяет локаторы в
записи.

```sh
cd deploy
docker compose exec -T nats-box sh /t/audit/audit.sh
```

Обе ветви в одной записи. Тело — бакет `waf-bodies`, заголовки — `waf-headers`:
локатор в обоих случаях архивный (`store=archive`, `driver=s3`, ключ из даты,
узла и `ray`). Срок хранения (`store.archive`, секунды) в записи остаётся: по
нему видно, когда объекта не станет.

Судьба самих ключей в Redis — в [body](../body/README.md): отсюда Redis не виден.

## Превью

Срез запроса в самой записи: заголовки, параметры и тело в трёх колонках
`waf.audit`. Дорога длиннее предыдущей — проверяется до ClickHouse, потому что
превью существует ради поиска, а ищут по колонке, а не по сообщению на шине.

```sh
cd deploy
docker compose exec -T nats-box sh /t/audit/preview.sh
```

Маршрут `/preview/` урезан до крошечных бюджетов (512 байт на заголовки, 128 на
параметры, 64 на тело) — на таких числах видно то, ради чего превью и
ограничено: секция обрывается на целой паре, а пара, не влезающая в остаток,
выпадает целиком, а не приезжает обрывком.

Потолок на одну пару (`item_max`) режет значение, не вытесняя остальные пары.
Бюджет секции остаётся вторым ограничением: пара, не влезающая в остаток, не
пишется вовсе. Сверху стоят абсолютные пределы чтения WAF:
`large_client_header_buffers` для заголовков и параметров,
`min(client_max_body_size, waf_body_limit)` для тела. Превью без размера означает
«весь объект» ровно в этих границах.

Тела на этом маршруте не просит ни один инспектор, поэтому стоит
`waf_preview body=64`: заданное превью само требует извлечь объект. Рядом стоит
`waf_body_limit 1k` при вчетверо большем теле — прочитанное ради записи тело
никуда не размещается, и ни локатора, ни политики `waf_body_limit` на маршруте
не возникает.

Запрет проверяется с обеих сторон. `x-preview-secret` запрещён маршрутом
(`waf_preview headers deny=x-preview-secret`), `cookie` и `authorization` —
встроенным списком модуля: список маршрута к встроенному добавляется, а не
заменяет его.

## Маркеры

`markers.sh` — метка события от профиля до поиска: инициатор modsec с
`do: mark` и меткой уникальной на прогон, боевой запрос с SQLi, дальше проверки
по пути метки — секция `markers` записи, `marker` в `actions` без адресата и без
исходов (соседям маркер не доставляют), фильтр `marker=` и группировка
`by=marker`. Отдельно проверено, что `mark` без метки контроллер не сохраняет.

Профиль правит и возвращает на место сам прогон (`trap ... EXIT`), синтетики
нет: прогон бьёт по живому маршруту защищаемого приложения и профилю modsec
`default`. Сервер `juice.waf.test`, на котором это было написано, снесён --
прогон ждёт нового тестового приложения. Устройство маркеров — [inspector-actions.md](../../inspector-actions.md#маркеры).

## Усечённое тело

Что инспектор правил сообщает о префиксе на маршруте `/body/truncate/`
(`waf_body_limit 1k trim`).

```sh
cd deploy
docker compose exec -T nats-box sh /t/audit/truncate.sh
```

Префикс JSON обрывается посреди строки и перестаёт быть документом. Движок
сообщает об ошибке разбора правилом 200002, `ARGS` остаются пустыми,
аномального счёта нет — и 942100, которое ищет SQLi именно в `ARGS`, не
срабатывает, хотя признак в префикс попал целиком.

То есть `trim` у структурированного тела — отказ от проверки содержимого, а
не проверка по началу тела. Видно это только здесь: клиенту уходит `200`, и по
коду ответа отказ от проверки неотличим от чистого запроса. Само размещение
префикса — в [body](../body/README.md).

Запись инспектора ищется по `ray` из записи запроса, а не последним сообщением
темы: на ту же тему пишет пульс инспектора, и последним легко оказывается он.
