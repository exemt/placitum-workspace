# ip — IP фильтр

Два слоя: probe кладёт `client_ip` в сообщение без nginx; HTTP идёт через
модуль, realip на `/ip*` читает `X-Forwarded-For`.

```sh
cd deploy
sh ../tests/ip/ip.sh
sh ../tests/ip/ip-large.sh              # GeoLite2 us (~300k) + 100 запросов
COUNTRY=ru sh ../tests/ip/ip-large.sh
LOAD=1 sh ../tests/ip/ip-large.sh       # + k6
docker compose exec -T loadgen k6 run /app/ip.js
```

`ip.sh` — профили default / admin / ext / heavy и неизвестный тег. Фикстуру
он заводит сам: наборы `e2e_ip_*`, составные наборы `e2e-*` и эти четыре
профиля создаются через API контроллера и рассылаются поколением, после чего
прогон ждёт применения пробой. Демо-дерево стенда (`deploy/ip/policy`,
монтируется поверх образа) живёт только до рассылки: первая же перекрывает
его целиком, поэтому ожидания
держит фикстура, а не файлы контейнера. Повторный запуск переписывает то же
самое — чужие профили при этом не трогаются.

Заведённое остаётся на стенде намеренно: `nginx.conf` ссылается на профили
`admin`, `ext`, `heavy` из `waf_inspector`, и без них маршруты `/ip-admin/`,
`/ip-ext/`, `/ip-heavy/` отвечают отказом на всё.
`ip-large.sh` заливает выгрузку страны в `deploy/ip/policy/lists/us.txt`, меряет
100 запросов и возвращает заглушку (в том числе по сигналу).
