# e2e

Сквозные прогоны контура. Живут в рабочем месте (`placitum-workspace`): клиенту они не нужны.

Статус на 13.09.2026: схема согласована, сброса ещё нет. Наборы перенесены из `tests/`
монорепы (`db0ea6a`) как есть.

## Правила

1. **Прогон идёт на стенде `placitum` и сбрасывает его.** Эталон — снимок томов стенда. Сброс
   стирает всё, что сделано на стенде после снимка, в том числе руками; во время прогона
   стендом не пользуются.
2. **Каждый набор начинается с эталона.** Перед набором стенд возвращается к снимку целиком:
   тома восстанавливаются из архивов, контейнеры создаются заново. Сбрасывается всё сразу:
   база и память контроллера, KV и потоки NATS, аудит ClickHouse, архив MinIO, Redis (томов у
   него нет, пустеет при пересоздании), поколение на крае, общая память модуля, память
   инспекторов. После прогона стенд тоже возвращается к эталону.
3. **Внутри набора — журнал.** Кейсы заводят объекты через API и сносят их в обратном порядке
   (`lib/stand.mjs`, `ledger().unwind()`), как принято с 10.09. Кейс, который нарочно ломает
   контур (роняет процесс, заливает очередь), помечается `reset: case` и получает эталон перед
   собой.
4. **Только публичные входы.** Всё заводится через API контроллера, трафик идёт через край,
   проверки читают API, ClickHouse, NATS и Redis. Монтировать профили и конфиги компонентов
   нельзя: на установке из репозиториев их на диске нет.
5. **Всё помечено прогоном.** У прогона свой id: запросы несут его в пути или заголовке,
   выборки из аудита фильтруют по нему. Имена объектов — с префиксом `e2e-`.
6. **Один прогон за раз** — замок `lib/lock.mjs`.

Почему одного журнала мало: он не убирает аудит, архив, записи keeper, корзины капчи, память
инспекторов и мусор упавшего прогона — отсюда нынешний `--clean`.

## Эталон

- **Что внутри:** стенд после установки из клонов (инфраструктура → миграции → компоненты) с
  зелёным дымом и тяжёлыми общими фикстурами, которые дорого заводить в каждом наборе
  (тестовый каталог гео и ASN).
- **Где:** `.baseline/<отпечаток>/<том>.tar`, в git не едет.
- **Отпечаток:** sha256 от ID образов всех сервисов, списка миграций контроллера и
  `docker compose config`. Сменился образ или схема — эталон снимается заново: старую базу под
  новый код не восстанавливаем.
- **Размер:** тома стенда на 13.09 — около 70 МБ (postgres 52, clickhouse 13, nats 6). ФС под
  Docker — ext4 без снимков, поэтому архивы tar.

## Сброс

1. `docker compose -p placitum … down` — контейнеры и сеть; тома остаются.
2. Каждый том проекта очищается и разворачивается из архива эталона.
3. `up -d --wait`.
4. Ждать сходимости: все ноды во флоте отчитались поколением эталона с `apply ok`, инспекторы и
   сервисы на месте. Внутренний Redis после пересоздания пуст — контроллер досылает блобы
   поколений сам, до минуты.

Оценка — 1–2 минуты; замерить на прототипе. Не путать со `stand/preprod/stand.sh reset`: тот
сносит тома, образы и секреты под установку с нуля.

## Раскладка

```
e2e/
  README.md          этот файл
  lib/               клиент API, журнал заведения, проверки, личности, WebSocket, замок
  logic/             автономные кейсы логики и их прогон
  load/              нагрузочные кейсы и прогон; генератор — loadgen/
  runner/            сценарии changes, convergence, modsec, response
  audit/ auth/ body/ captcha/ combo/ counter/ dataset/ e2e/ http/ ip/ json/ keeper/
  lists/ modsec/ modsec-vlai/ procs/ pulse/ rewrite/ vlai/
                     shell-наборы стенда Windows; большинство мертвы после сноса синтетики
  fixtures/          канон профилей
  e2e-inventory.md   опись: что проверяет каждый прогон и на чём завязан
  testapp/           витрина shop.waf.test — из testapp/ монорепы
  loadgen/           генератор нагрузки — из deploy/loadgen/
```

Будут: `e2e.sh` (`baseline | reset | run [набор…]`), `.baseline/`, `reports/`.

## Оживление на стенде mvm

Ссылки внутри наборов ещё смотрят в монорепу (`../deploy`, `../inspectors/…`,
`controller/src/…`) и на стенд Windows (`127.0.0.1:8080`, `nginx-1`, `shop.waf.test`). Порядок:

1. `lib` и `logic` — уже автономны: первый зелёный набор.
2. `runner`: `changes`, `convergence` — от маршрутов не зависят.
3. `load` и `loadgen`.
4. Shell-наборы — переписать на кейсы через API поверх витрины.

`lib/bootstrap.mjs` не нужен: он собирал и раскатывал образы из дерева монорепы. Его роль берут
эталон и сброс.

## Открытое

- **Где раннер:** на хосте mvm (Node 24 есть) по портам стенда или контейнером в сети
  `placitum_default` — решится на первом наборе.
- **Витрина:** `testapp` поднять сервисом рядом с контуром (надстройка compose) и завести ей
  апстрим и сервер — в эталоне или в наборе.
