# Инспекторы: кто что проверяет и что у кого крутить

Профили любого инспектора: `profile_list` / `profile_get` / `profile_save`.
После правки профиля канал инспектора издаётся через `publish`. Что включено
на конкретном маршруте — `route_get` (блок `waf`).

## modsec — правила ModSecurity (CRS)

Основной сигнатурный слой: набор правил Core Rule Set плюс свои. Работает
суммой аномалии: правила добавляют очки, порог превышен — вердикт deny с
кодом `CRS_ANOMALY`.

Профиль (канал `rules`) — это состав правил и их обработка. Типичные ручки
оператора:

- **исключение правила**: точечно снять правило, которое ложно стреляет —
  на профиле, которым пользуется маршрут клиента;
- **порог аномалии**: жёстче или мягче в целом;
- **данные к правилам**: операторы `*FromFile` читают контентные наборы
  (kind=content) — их правит `dataset_content_set`, издания не требуют
  отдельного, но профиль правил должен быть издан.

У профилей из поставки есть «восстановить» (`profile_restore`) — вернуть к
дистрибутиву, если правки завели не туда.

## ip — адреса, страны, автономные системы

Решения по адресу клиента: разрешить, заблокировать, пометить. Профиль
ссылается на адресные наборы (kind=list), на списки стран и ASN. Есть
встроенные наборы (default allowlist/blocklist) и клиентские.

Быстрая реакция — не правка профиля, а записи в наборы: `addresses_add` с
`ttl_s` (временная блокировка), `addresses_remove` (разблокировать),
`address_find` (где адрес уже числится). Записи доезжают живьём.

## counter — счётчики и лимиты

Считает события по корзинам и сравнивает с лимитами: частота запросов,
повторы, пороги по ключу (адрес, сессия, путь). Умеет принимать пометки
(note) от других инспекторов и считать по ним.

## captcha — проверка человеком

Выдаёт вызов при подозрении и пропускает решивших. Профиль: провайдер
капчи (+ запасной), корзины — кого и как часто вызывать. Один провайдер на
профиль.

## auth — сессии и аутентификация

Следит за сессиями приложения: связывает запросы в сессию по куке,
пространство сессий определяется именем куки.

## json — контракт API

Проверяет тела JSON на соответствие контракту API: структура, типы, лишние
поля. Для маршрутов API, где формат известен.

## vlai — поведенческий анализ

Оценивает запросы моделью (скор), профиль задаёт режим и приём вердиктов.
Пишет свои находки в журнал как остальные; может пополнять адресные наборы.

## action — канал действий

Сам ничего не проверяет: раздаёт соседям подсказки по маршруту — порог
(threshold, в процентах к измерению), пометку (note), пропуск (skip),
переключение групп модификатора (mutate). Через него инспекторы влияют друг
на друга без прямой связи.

## rewrite — модификация ответов

Правит то, что уходит клиенту: удаление/замена/вставка по регулярным
выражениям в теле ответа, операции над заголовками. Профиль — группы
модификаторов с условиями по коду и типу; выключенные группы включаются
просьбой mutate от соседей. Тело переписывается в обменнике (Redis), модуль
поднимает копию сам; фаза одна — ответ, маршрут обязан держать
`waf_hold response gate`. Издаётся каналом `rewrite`.

## Локальный слой маршрута

Помимо инспекторов, у маршрута есть локальные проверки самой ноды (блок
`waf` в документе маршрута): условия, селекторы, лимиты. Порядок проверок
значим: сначала check-проверки, затем rate. Правится через `route_update`,
издаётся каналом `nginx`.
