# Контур WAF глазами оператора

## Из чего состоит

Трафик клиента принимают **ноды** — nginx с агентом. Нода сама ничего не
решает про атаки: на каждый проверяемый запрос она опрашивает **инспекторов**
— отдельные процессы, каждый со своей специальностью (правила ModSecurity,
репутация адреса, лимиты, капча и т.д.). Инспекторы отвечают вердиктами, нода
сводит их и либо пропускает запрос, либо отдаёт страницу отказа.

Настраивается всё через **контроллер** — тот самый API, в который ходят
инструменты этого сервера. Контроллер держит конфигурацию в базе, панель и
эти инструменты правят её через одни и те же ручки.

Каждый проверенный запрос остаётся в **журнале**: запись со всеми вердиктами
и находками, плюс сырьё (заголовки, аргументы, тело) в обменнике. Ключ записи —
пара `node` + `ray`.

## Как устроена конфигурация

- **Пространство** (space) — верхний уровень изоляции; обычно оно одно,
  сервер MCP прибит к одному пространству.
- **Сервер** — виртуальный хост (по `server_names`), у него список
  **маршрутов** (location). Порядок маршрутов имеет значение.
- На маршруте живёт блок `waf`: включён ли WAF и какие инспекторы с какими
  профилями его проверяют. Настройки наследуются: пространство → сервер →
  маршрут; в документе наследования видно, что переопределено, а что пришло
  сверху.
- **Профиль** — документ настройки одного инспектора (набор правил modsec,
  политика адресов, корзины лимитов…). Маршруты ссылаются на профили по
  имени; один профиль можно использовать на многих маршрутах.
- **Наборы данных** — списки, на которые ссылаются профили: адресные
  (kind=list — блокировки, разрешения) и контентные (kind=content — данные к
  правилам, страницы).

## Правка → издание → применение

Правка через API меняет только **сохранённое** состояние. Чтобы участники
контура её увидели, канал надо **издать** (`publish`). Дальше участники сами
забирают новое поколение и подтверждают применение.

Три уровня видны в сходимости (`convergence_status`):

- `dirty` — есть сохранённые, но не изданные правки;
- издано, но участники ещё не применили — канал не `ok`;
- всё сошлось — канал `ok`, лампа зелёная.

Каналы: `nginx` (конфиг nginx: серверы, маршруты, блок waf), `agent`
(настройки агента), `rules` (профили правил modsec), `ip`, `auth`, `captcha`,
`json`, `action`, `counter`, `vlai` (профили соответствующих инспекторов).

Исключение: **записи адресных наборов** (addresses_add / addresses_remove)
доезжают до участников живьём, без издания — это рычаг быстрой реакции.

## Правила безопасной работы

- Сначала смотреть, потом крутить: `waf_map` + `fleet_status` в начале
  сессии, `attacks_search`/`attack_card` до любой правки.
- Правки узкие: точечное исключение правила лучше отключения группы;
  временная блокировка с `ttl_s` лучше бессрочной.
- После `publish` проверять и сходимость (все каналы `ok`), и эффект в
  журнале: атака перестала проходить, легитимный трафик не отвалился.
- Ошибки контроллера (409 `in_use`, 422 с полями) — это ответы, а не сбои:
  читать и действовать по ним.
