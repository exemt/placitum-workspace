# Сообщения на шине

Шина контура — NATS. У неё две несмешивающиеся плоскости, и путать их нельзя.

**Горячий путь — core NATS, scatter-gather.** Модуль в воркере nginx публикует вопрос на subject
инспектора и указывает свой inbox в `reply-to`; инспектор отвечает в этот inbox. Доставка без
гарантий и без очереди на диске: опоздавший ответ никому не нужен, потому что решение по запросу
уже принято, а исход опоздания определяет политика дедлайна на маршруте. Формат — JSON.

**Поток записей — JetStream.** Аудит, детали находок и журналы едут отдельно от решения: они
переживают перезапуск потребителя, и их читают минутами и часами позже, а не миллисекундами.
Публикуются они **после** ответа в inbox — деталями отчёта дедлайн волны двигать нельзя.

Правило, из которого выводится всё остальное: **в горячем пути едет решение, а не содержимое.**
Тела, заголовки и строка запроса ходят через обменник по ключу; в сообщении — локатор. Причина не в
экономии, а в том, что длину задаёт клиент, а сообщение публикуется по одному на каждого инспектора
волны.
