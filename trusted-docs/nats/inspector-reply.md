# Ответ инспектора модулю

Единственное сообщение горячего пути, которое инспектор пишет сам. В нём едет решение по запросу и
переопределения, которые модуль применит к трафику. Всё, чем решение объясняется, — находки, номера
правил, тайминги движка — уезжает отдельным сообщением в JetStream и в этом контракте не участвует.

## Транспорт

```
модуль:     PUB waf.req.<имя>   reply-to _INBOX.waf.<node>.<pid>.<nonce>.v.<rid>.<ii>
инспектор:  PUB _INBOX.waf.<node>.<pid>.<nonce>.v.<rid>.<ii>   ← тело ниже
```

Адрес разбирать не нужно: инспектор отвечает ровно на то, что стоит в `reply-to`. Ответ обязателен
даже на нераспарсенное сообщение — молчание модуль не отличит от перегрузки и будет ждать до
дедлайна волны. Ради такого ответа `rid` вынимают из мусора отдельно.

Формат — JSON, одно сообщение на один вопрос.

## Каркас

```json
{
  "v": 2,
  "rid": "480000013b000000",
  "inspector": "modsec",
  "verdict": "allow",
  "score": 0,
  "reason": { "code": "…", "scope": "…", "subject": "…", "retry": 0 },
  "response": { "name": "blocked" },
  "redirect": { "url": "…", "status": 303 },
  "headers":  { "set": {}, "unset": [] },
  "args":     { "set": {}, "unset": [] },
  "rewrite":  { "body": { "key": "…", "size": 0, "sha256": "…" },
                "content_type": "…", "groups": [] },
  "cookies":  [ { "name": "…", "value": "…", "path": "/", "max_age": 300 } ],
  "sessions": [ { "source": "…", "kind": "own", "user": "…", "id": "…", "verified": true } ],
  "continue": { "subject": "…", "ttl_ms": 30000 },
  "actions":  [ { "to": "…", "do": "…", "apply": "…", "code": "…" } ],
  "cache": true
}
```

Это полное множество полей, которые читает приёмник, — все шестнадцать. Вместе они не едут никогда:
секции взаимоисключающие по фазе и вердикту. Настоящее сообщение состоит из обязательного минимума
и одной-двух секций.

Обязательный минимум — четыре поля:

```json
{"v": 2, "rid": "480000013b000000", "inspector": "modsec", "verdict": "allow"}
```

`v`, `rid` и `inspector` — эхо из вопроса, а не значения из конфигурации сервиса: под каким именем
процесс объявлен в nginx, знает только само сообщение. `rid` не совпал с ожидаемым или `inspector`
не входит в маску текущей волны — ответ не учитывается.

## Поля

| Поле | Тип | Когда | Что делает модуль |
| --- | --- | --- | --- |
| `v` | целое | всегда | Сверяет с версией протокола; чужая версия — ответ отброшен |
| `rid` | строка, 16 hex | всегда | Находит слот ожидания. Это адрес слота, а не идентичность запроса — та в `ray` |
| `inspector` | строка | всегда | Сверяет с маской волны: чей это голос |
| `verdict` | `allow` \| `score` \| `deny` \| `redirect` \| `error` | всегда | Решение — или признанное его отсутствие (`error`). Единственное, ради чего волна ждёт ответа |
| `score` | целое 0–100 | при `verdict: score` | Добавляет к сумме фазы как прислано: множителя на вызове нет. При других вердиктах поле игнорируется |
| `reason.code` | строка | при `deny`, `redirect`, `error` и ненулевом счёте | Код для оператора: лог, диагностический заголовок, выбор записи каталога отказов. Клиенту не показывается |
| `reason.scope` | словарь: `address`, `network`, `country`, `asn`, `session`, `request` | по желанию, при `deny` | Кладёт в `$waf_deny_scope`: по нему ветвится страница отказа |
| `reason.subject` | строка ≤64 байт, алфавит `[A-Za-z0-9.:/_-]` | по желанию, при `deny` | Кладёт в `$waf_deny_subject`: чем названо закрытое — адрес, сеть, код страны, номер AS |
| `reason.retry` | целое, **секунды**, `1..2592000` | по желанию, при `deny` | Кладёт в `$waf_deny_retry`; страница печатает «Повторить можно через N с.». Заголовка `Retry-After` из него не делает |
| `response.name` | строка | при `deny` | Имя записи каталога `waf_deny_response` — не файл страницы. Запись держит `type=`, `status=`, `page=@location` и гейт `params=`; страницу отдаёт nginx. Нет поля — `waf_deny_response_default` |
| `redirect.url` | строка | при `verdict: redirect` | Ведёт клиента, предварительно проверив адрес по `waf_redirect_allow` маршрута |
| `redirect.status` | `302` \| `303` \| `307` | по желанию | Код перенаправления; умолчание `303` |
| `headers.set` / `unset` | объект / массив имён | request и response | Правит заголовки запроса перед проксированием либо ответа перед отдачей |
| `args.set` / `unset` | объект / массив имён | request, при `allow` | Правит пары строки запроса по именам, байты в проводном виде. Только при `waf_send request args=store` |
| `rewrite.body.key` | строка | с секцией `body` | Поднимает объект из обменника и отдаёт его вместо тела. Ключ производный от локатора из вопроса плюс суффикс `[a-z0-9_-]{1,32}`; принятая подмена становится локатором следующей волны, и та наращивает ключ на нём |
| `rewrite.body.size` | целое | с секцией `body` | Сверяет с прочитанным байт-в-байт; разошлось — подмена не состоялась |
| `rewrite.body.sha256` | hex-строка | по желанию | Сверяет после чтения |
| `rewrite.content_type` | строка ≤128 байт | тело отказа фазы запроса | Ставит тип этого тела; умолчание `text/html; charset=utf-8`. На фазе ответа не читается |
| `rewrite.groups` | массив имён, до 16 | по желанию | Не толкует: имена применённых групп профиля уезжают в лог и запись аудита как расписка, чем текст изменён |
| `cookies[]` | `name`, `value`, `path`, `max_age` | request | Ставит клиенту. `secure`, `http_only`, `same_site` разбирает, но берёт из `waf_cookie_defaults`; `domain` отбрасывает — cookie host-only |
| `sessions[]` | `source`, `kind`, `user`, `id`, `verified`, `issued`, `expires`, `groups` | request, до 4 записей в ответе | Ничего не применяет: переносит в `sessions[]` записи аудита, дописав имя отправителя. На запрос суммарно до 8 записей |
| `continue.subject` | строка | request, при `keep=on` | Запоминает личный адрес экземпляра и публикует туда сообщение поздней фазы — при `resume=prefer\|require` |
| `continue.ttl_ms` | целое, миллисекунды | с `continue` | Сколько экземпляр обещает держать состояние |
| `actions[]` | `to`, `do`, `apply`, плюс параметры глагола | любая фаза | Проверяет форму, ограничивает числом и размером, переносит в `prior` следующей волны. Не исполняет — кроме тех просьб, чей адресат он сам: режим вызова соседа, журнал, архив, маркер, очки (`do: score`, `value` со знаком к сумме фазы; от пассивного отбрасывается) |
| `cache` | булево | фаза кадров | `false` — не запоминать вердикт по хешу кадра в `waf_frame_cache`. Отсутствие равнозначно `true` |

## «Проверить не смог»

Инспектор перегружен, не знает профиля, разъехался с версией схемы, не поднялся его движок. Это не
вердикт, а признанное его отсутствие:

```json
{
  "v": 2,
  "rid": "480000013b000000",
  "inspector": "modsec",
  "verdict": "error",
  "reason": { "code": "MODSEC_QUEUE_LIMIT" }
}
```

`reason.code` обязателен — без него событие неотличимо от молчания в журнале.

Модуль трактует такой ответ как отсутствие вердикта: обязательный инспектор срывает волну сразу
(код итога `fail_inspector`, дедлайна ждать незачем — ответ уже пришёл), пассивный не срывает
ничего. Исход выбирает маршрут: `waf_exception <фаза> inspector pass|deny [response=<имя>]`,
умолчание — `deny`.

Всё остальное в таком ответе выбрасывается: счёт, `headers`, `args`, `rewrite`, `cookies`,
`continue`, `actions`. Инспектор, не выполнивший работу, не вправе и просить о чужой. `sessions`
остаются: они ничего не применяют, а «кого видели» — правда и при сбое.

Предохранитель считает `error` отказом наравне с молчанием и мусором: иначе появился бы способ быть
сломанным и здоровым одновременно.

## Как вердикт читается по режиму вызова

Инспектор о режиме своего вызова на маршруте не знает и отвечает одинаково; что из ответа берётся,
решает `mode=` строки `waf_inspect`:

| Режим | `score` | `deny` / `redirect` | `headers`, `args`, `cookies`, `rewrite` | `actions`, видимость в `prior` |
| --- | --- | --- | --- | --- |
| `active` | в сумму | гейтит | применяются | да |
| `vote` | в сумму | `deny` — сто очков в сумму, `redirect` — только в журнал | не применяются | да, вердикт как сказан, `score` — что легло в сумму |
| `passive` | в теневую сумму | только в журнал | не применяются | нет |

`sessions` и `continue` читаются при любом режиме: первые ничего не применяют, второе — адрес
экземпляра, а не решение.

## Что из этого где разрешено

| Секция | Фаза | Вердикт |
| --- | --- | --- |
| `score` | любая | `score` |
| `reason` | любая | любой |
| `response` | любая | `deny` |
| `redirect` | request | `redirect` |
| `headers` | request, response | любой |
| `args` | request | `allow` |
| `rewrite` | request, response, frame | `allow`, `deny` |
| `cookies` | request | `redirect`, `deny` |
| `sessions` | request | любой |
| `continue` | request | любой |
| `actions` | любая | любой |
| `cache` | frame | любой |

Отдельного права на подмену нет: `mutate=on` в реестре снят, и `rewrite`, `args` и заголовки фазы
ответа принимаются от любой декларации. Две секции `rewrite` на одной волне — не конкурс, а сбой
класса `body` у `waf_exception` фазы.

Вердикт `redirect` запрещён на фазе ответа и на кадрах: перенаправлять уже некого. Секция `headers`
на кадре не применяется — у кадра их нет.

## Как приёмник читает сообщение

**Незнакомое поле пропускается молча.** Это правило совместимости: инспектор новее модуля не должен
ронять ответ лишним ключом.

`verdict: "error"` без `reason.code` — битый ответ, как и всё ниже.

**Часть ошибок отбраковывает ответ целиком.** Не «поле проигнорировано» — весь ответ, и волна
продолжает ждать так, будто инспектор промолчал; исход тогда определяет политика дедлайна маршрута.
Так поступают с: чужой версией `v`, отсутствующим `verdict`, `verdict: score` без `score`,
дробным/отрицательным/большим ста счётом, `verdict: redirect` без адреса или с адресом, не прошедшим
проверку, запрещённым именем заголовка и CR/LF/NUL в имени либо значении, битой формой `args`,
секцией `rewrite.body` без `key` или без `size`, пятой записью в `sessions`, незнакомым глаголом или
осью в `actions`, размером ответа сверх `waf_reply_max`.

**Часть значений гасится молча, а вердикт остаётся в силе.** Так поступают только с публичной
тройкой `reason`: `scope` вне словаря, `subject` длиннее 64 байт или с посторонним символом, `retry`
вне `1..2592000`. Инспектор, ошибшийся в объяснении, не должен отменять само решение.

**Часть полей просто теряет смысл.** `score` при вердикте, отличном от `score`, обнуляется;
`redirect.url` и `status` при вердикте, отличном от `redirect`, стираются.

С провода не принимается ничего, что модуль обязан решать сам: HTTP-код отказа, путь или содержимое
страницы, режим вызова, порог маршрута, атрибуты cookie, имя автора в `prior`. Единственное
исключение — цель редиректа, и она проходит отдельную проверку.

Сюда же попадает исход несостоявшейся подмены. Объект из `rewrite` не поднялся — ключ пропал,
размер разошёлся, снимок оказался неполным: это ошибка обработки запроса, и решает её политика фазы
`waf_exception <фаза> body` (`deny` — отказ, `pass` — оригинал с WARN).
Полей `on_error` и `response` в секции `rewrite` нет — как нет и одноимённых опций у `waf_send`:
инспектор о доступности объекта знает не больше модуля, и три рычага об одном расходились бы между
собой.
