# Обменник

Горячее хранилище контура — Redis. Он один на все ноды, всех инспекторов и агента, и потому у него
нет имени: называть можно то, из чего выбирают.

Правило, из которого выводится всё остальное: **в горячем пути едет решение, а не содержимое.** Тело,
заголовки и строка запроса не помещаются в сообщение волны — они кладутся в обменник тремя ключами, а
на проводе едет локатор. Причина не в экономии: длину задаёт клиент, а сообщение публикуется по
одному на каждого инспектора волны.

Из этого следует разделение сторон, которое стоит держать в голове при чтении раздела:

**Пишет только модуль nginx.** Ни один инспектор и ни агент не кладут в обменник объекты запроса.
Единственная чужая запись — подменённое тело от инспектора, и лежит она под своим
ключом, производным от локатора; модуль её читает, но не создаёт.

**Удаляет тоже модуль** — сразу, как отпускает запрос, — кроме объектов, которые он оставил агенту.
Оставленные удаляет агент, забрав их в архив; TTL ключа здесь только страховка на случай, если агент
до объекта не доберётся.
