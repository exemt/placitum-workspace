# Запись объектов в обменник

Три объекта запроса — `headers`, `args`, `body` — модуль кладёт в Redis, а на провод отдаёт локатор.
Эта страница о том, какие директивы приводят к записи, что оказывается в ключе, в значении и в сроке
жизни, и чего от директив ждать нельзя.

Запись в коде модуля ровно две: `ngx_http_waf_meta_place_blob()` кладёт заголовки и строку запроса,
`ngx_http_waf_body_decide()` — тело. Обе зовут `driver->put()`, третьего вызова нет. Всё, что
описано ниже, — это то, чем директивы управляют этими двумя вызовами.

## Директивы

| Директива | Уровень | Что решает в записи |
| --- | --- | --- |
| `waf_store` | `http`, один раз | Есть ли обменник вообще, где он, каким сроком и каким потолком объекта |
| `waf_capture` | `http`, `server`, `location` | Какие из трёх объектов кладутся и сколько байт |
| `waf_capture … mask=` / `deny=` | те же | Чем заменяется и что выбрасывается **до** записи |
| `waf_archive` | те же | Какой из двух сроков выберет `put` и кому достанется ключ после вердикта |
| `waf_archive … reload` | те же | Второй `put`: оригинал поверх снятого, после закрытия волн и только на исходе, где архив объект берёт |
| `waf_preview … reload` | те же | То же самое, ради записи аудита; делается на любом исходе |
| `waf_body_limit` | те же | Потолок тела и что делать с запросом при превышении |
| `waf_body_max_holds` | `http` | Сколько размещений воркер держит одновременно |
| `waf_node_id` | `http` | Первое поле ключа |

`waf_send` в этом списке нет: `=store` — это чтение (`GET`) того, что положил инспектор, а не запись.
Простой `waf_preview` без слова `reload` тоже не пишет — его срез уезжает в саму запись аудита.

Фаза — обязательное первое слово у `waf_capture`, `waf_archive`, `waf_preview` и `waf_body_limit`:
`request`, `response`, `frame`, `frame:c2s`, `frame:s2c`. Формы `waf_capture off;` и
`waf_preview none;` без фазы конфигурация не принимает — фаза разбирается раньше, и слово `off`
на её месте отвергается как не-фаза.

Словарь объектов у фазы свой: у запроса три, у ответа `headers` и `body`, у кадра только `body`.
Названный вне своего словаря объект — ошибка `nginx -t`.

## waf_store: без него записи нет

```nginx
waf_store driver=redis url=redis://redis:6379 ttl=30s retain_ttl=5m max=8m;
```

Объявляется один раз на `http` и не выбирается маршрутом. Вторая строка — `is duplicate`.

| Опция | Умолчание | Что делает |
| --- | --- | --- |
| `driver=` | нет | Разбирается раньше остальных опций; встроенные — `redis`, `inline`, `none` |
| `url=` | нет, обязательна | `redis://host:port` или `host:port`, порт по умолчанию 6379; несколько через запятую. Адреса резолвятся при загрузке конфигурации |
| `ttl=` | `30s` | Срок обычного объекта. `0` — писать без `PX` |
| `retain_ttl=` | `5m` | Срок объекта, за которым придёт агент |
| `max=` | `8m` | Потолок одного значения; выше `512m` конфигурация не принимает |
| `pool=` | `4` | Соединений на воркер, `1..64` |
| `connect_timeout=` | `200ms` | |
| `op_timeout=` | `100ms` | Срок `SET` и `DEL` |
| `get_timeout=` | `500ms` | Свой срок у `GET`: он тянет целое тело |
| `reconnect_wait=` | `500ms` | |
| `user=`, `db=` | — | |
| `password_file=` | — | Пароль только файлом |

`password=` в тексте конфигурации отвергается: файл конфигурации читают все, кому нужен маршрут, а
секрет обменника — это доступ ко всем телам контура. `tls`, `tls_*`, `cluster` и `sentinel`
отвергаются как ещё не реализованные, а не игнорируются молча.

Несколько адресов — это отказоустойчивость, а не шардирование: воркер работает с одним из них, а
инспектор находит ключ по подсказке `hint` в локаторе. `nginx -t` печатает об этом notice.

`retain_ttl` ниже `ttl` (при обоих ненулевых) — ошибка: маршрут с архивацией терял бы ключи раньше
маршрута без неё.

Драйверы `none` и `inline` — не обменник: они не видны другим хостам, и маршрут, который
кладёт хоть один объект, при них не собирается.

## waf_capture: что и сколько кладётся

```nginx
waf_capture request headers args body=64k;
waf_capture request none;
waf_capture response headers=8k;
```

Единственная ось, которая решает, какие объекты вообще размещаются для инспекторов. Заявка самого
инспектора ничего к ней не добавляет и её не сужает: набор волны — это `capture` маршрута, и он же
уезжает в поле `needs` сообщения одинаковым для всех инспекторов волны.

Без `=` — объект целиком. `=<size>` — потолок размещаемого. `=none` — этот вид выключен, остальные
слова строки не тронуты. Одно слово `none` или `off` вместо списка выключает фазу целиком и не
комбинируется ни с чем.

Строки одного уровня складываются по объекту; своя строка на `location` перекрывает только названный
вид. Дважды названный на одном уровне объект — ошибка.

**Умолчание есть только у фазы запроса:** `headers` и `args` целиком. У ответа и у кадров без строки
не снимается ничего.

Объект, названный в `capture`, кладётся только при живых волнах фазы: маршрут без инспекторов не
обращается к обменнику, даже если `capture` унаследован сверху.

**`=<size>` у `capture` — это и есть размер `put` перед волной.** Снимок кладётся ровно в размере
`capture`, и волна ждёт только его: архив и превью размещение снимка не расширяют. Их оригинал
докладывает второй `put` уже после вердикта (см. «Второй put: reload»), в максимум размеров строк
`reload` архива и превью. У кадров второго `put` нет: там размещение сразу считается максимумом
из `capture`, `waf_archive` и `waf_preview`, потому что вся нагрузка лежит в буфере до вердикта, а
масок у кадра нет. Инспектору в любом случае показывают `size`, урезанный по `capture`: сверх
снятого ему смотреть нечего.

### mask= и deny=

Отдельными строками, по одному объекту на строку:

```nginx
waf_capture request headers deny=authorization,cookie;
waf_capture request args mask=token,password;
```

`deny=` выбрасывает пару целиком, `mask=` заменяет значение шестидесятичетырёхсимвольным SHA-256 от
него в hex. Обе правки делаются **до** записи: в Redis ложится уже обработанный объект, и оригинала
там в этот момент нет ни у кого.

Имена сравниваются без учёта регистра. Допустимый алфавит имени — `[A-Za-z0-9._-]`; `*` и `none` в
этих списках отвергаются как «пустая секция». `body` списков не принимает вовсе — объект и так один
префикс. `allow=` у `waf_capture` нет (он есть только у `waf_archive` и `waf_preview`).

## Что оказывается в значении

| Объект | Значение | Как режется по лимиту |
| --- | --- | --- |
| `headers` | JSON-массив пар: `[["Host","example.com"],["User-Agent","curl/8"]]` | По целым парам: не влезшая пара и все за ней остаются за скобкой. Пустой массив — валидный JSON |
| `args` | Строка запроса байтами, как пришла (после `deny=`/`mask=`, если они есть) | По байтам, оборвать может посреди пары |
| `body` | Сырые байты, префикс тела | По байтам |

Имена заголовков — как их прислал клиент, регистр не нормализуется. Заголовки фазы ответа берутся из
`headers_out` вместе с полями, которые nginx держит отдельно.

Значение всегда в открытом виде. Поля `enc`, `transformed` и `processed_sha256`, которые понимает
читающая сторона, модуль не выставляет никогда.

Пустой объект не кладётся и локатора не получает: инспектор увидит `null` и не обязан отличать «не
прислали» от «не смогли положить».

`sha256`, `complete` и `truncated` в локаторе есть только у тела; хеш считается по телу **целиком**,
сколько бы из него ни легло, — он связывает событие с архивом, а в архиве оригинал.

Размер в локаторе, который видит инспектор, урезан по `capture`, даже когда в Redis лежит больше —
а лежит больше у кадра, где размещение расширили `waf_archive`/`waf_preview`, и у запроса после
`reload`, которого инспекторы уже не застают. Флаги `complete` и `truncated` считаются от объекта
целиком, а не от `capture`: тело, положенное целиком и урезанное только в локаторе, остаётся
`complete: true`; тело, положенное снимком в 4k из 20k, до `reload` лежит с `truncated: true`, а
после него в том же ключе лежат 20k.

## Ключ и срок

```
<waf_node_id>:<rid>:<фаза>[:<объект>]
```

Позиционный ключ, а не хеш содержимого: хеш требовал бы полного прохода по телу до начала записи.

* Тег фазы — `req`, `rsp`, `frm`. Оба направления кадра пишут `frm`; различает их `rid`, который у
  каждого кадра свой.
* Суффикс объекта — `hdr` у заголовков, `arg` у строки запроса. У тела суффикса нет.
* `rid` — 16 hex-символов, берётся вместе со слотом ожидания. Слот берётся **до** размещения, иначе
  объекты уехали бы под прочерками.

Команда — `SET <ключ> <байты> PX <мс>`, либо `SET <ключ> <байты>` при `ttl=0`. Перед волной — один
`put` на объект и фазу: ретрая в горячем пути нет, потому что он удваивает латентность в худший
момент. Второй `put` в тот же ключ бывает только у `reload`, после вердикта.

Срок выбирается **в момент записи** и позже не продлевается — `EXPIRE` модуль не шлёт никогда:

* `retain_ttl` — если объект назван в `waf_archive` этой фазы маршрута;
* `ttl` — во всех остальных случаях.

Из этого следует то, что стоит знать заранее: объект, оставленный агенту по просьбе соседа на
маршруте, где `waf_archive` нет вовсе, лежит под коротким `ttl`. Просьба
меняет владельца ключа, но не его срок.

Удаление — `DEL` при освобождении запроса. Ключ не удаляется в двух случаях: объект оставлен агенту,
либо соединения с Redis в этот момент нет — тогда ключ доживает на TTL.

## Второй put: reload

`mask=` и `deny=` портят объект для всех, включая архив и запись аудита, а размер снимка режет его
для всех, включая агента. `reload` возвращает оригинал: после того как все волны закрыты, модуль
собирает объект заново, уже без списков и в размере строки `reload`, и пишет его **в тот же ключ**
поверх снятого. Инспекторы этой правки не видят — их уже нет.

```nginx
waf_archive request reload headers=capture body ttl=180d when=deny;
waf_preview request reload headers=capture;
```

**`reload` — это отдельная форма строки, а не опция объекта.** Слово стоит сразу после фазы, объекты
перечисляются после него. `waf_archive request headers reload=capture` конфигурация не принимает:
`unknown option "reload" in waf_archive`.

Величина у объекта в строке `reload`: без `=` — весь объект, `=capture` — столько же, сколько снято,
`=<size>` — явный размер. Записи предшествует чтение тела, если его ещё не читали.

**Второй `put` делается только тогда, когда он что-то меняет и кому-то нужен.**

* Оригинал только ради архива не кладётся на исходе, на котором архив объект не берёт: `when=deny`
  на допущенном запросе означает один `put` на объект, а не два и `DEL`. Исход для этого берётся
  маршрутный: пока впереди фаза ответа (её отказ считается и объектам запроса) или на фазе запроса
  стоит `waf_send request body=store` (сорвавшийся подъём подмены при политике `block` — отказ),
  оригинал кладётся на любом исходе. Ради превью (`waf_preview … reload`) он кладётся всегда:
  запись пишется на любом исходе.
* Те же байты второй раз не кладутся. У заголовков и строки запроса оригинал собирается и
  сравнивается с положенным: списки, которые ничего не тронули, и размер, который не вырос, дают тот
  же объект — `put` пропускается. У тела масок нет вовсе, и `reload` для него — только ширина:
  второй `put` есть, лишь когда строка `reload` просит больше байт, чем легло снимком.
* Тело, нужное только архиву или превью (в `capture` его нет), читается после вердикта и тем же
  правилом: на допуске при `when=deny` его не читают вовсе.

Просьбу о том же может прислать сосед: глагол записи с `source original` -- гранта под него нет,
принимается от любого спрошенного инспектора; она кладёт оригинал на любом исходе. Просьба «как снято» (`store`) наоборот
глушит `reload` маршрута у названных объектов.

Агенту вместе с набором архива уезжает, какие имена в объекте уже хеш: поле `hashed` у объекта в
секции `archive` записи — это `mask=` снимка, если объект так и остался видом инспекторов (`reload`
его не перекладывал или не смог). Маска архива на такое имя второй раз не хеширует: в S3 тот же
sha256, что видели инспекторы и что лежит в записи. После удачного `reload` поля нет — маска архива
хеширует оригинал.

`allow=` и `mask=` архива или превью на имя, которое `deny=` снимка выбросил, без `reload` этого
объекта — ошибка `nginx -t`: имени в объекте уже нет, и обещание не сбылось бы молча.

`reload` не бывает у кадров: у кадра нет масок, вся нагрузка лежит в буфере до вердикта, и архив с
превью расширяют размещение сами. `nginx -t` на `waf_archive frame … reload` отвечает отказом с
подсказкой задать размер напрямую.

Вне фазы запроса `reload` шире снимка не принимается: у ответа держится ровно то, что снято, а всё
сверх снимка уже ушло получателю.

## waf_archive: срок и владелец

```nginx
waf_archive request body=8k ttl=180d when=deny;
waf_archive request none;
```

Директива меняет запись в двух местах: выбирает `retain_ttl` вместо `ttl` и оставляет ключ агенту
вместо `DEL`. Размер на объекте (`body=8k`) режет **агент**, уже при отправке в архив: в обменнике
лежит столько, сколько положил снимок, — урезать общий объект ради настройки архива модуль не
вправе, его мог попросить инспектор.

`when=` принимает только `allow` и `deny`; без `when=` архивируется любой исход, включая редирект.
Слова `always` и `redirect` отвергаются явным сообщением. Исход берётся у маршрута, а не у фазы:
`when=deny` на запросе срабатывает и тогда, когда отказала фаза ответа.

Сам по себе `waf_archive` размещения не расширяет: объект, названный в архиве, обязан быть в
`waf_capture`, иначе `nginx -t` требует написать `reload`. Это верно и для кадра — у кадра снята
только другая проверка, на **размер**: там архив может быть шире снятого без `reload`, потому что
весь кадр лежит в буфере до вердикта и размещение расширяется само.

Ключ остаётся агенту только у запроса, попавшего в запись аудита. Оборванный до вердикта запрос и
кадр без записи ключи не оставляют: держать до `retain_ttl` объект, за которым никто не придёт,
незачем.

## Потолки

`waf_body_limit <фаза> <размер> [block|pass|trim]` — умолчание `1m` и `block`, и оно наследуется
фазой ответа и кадрами от фазы запроса.

* `block` — тело сверх лимита не кладётся, запрос отбивается этой же политикой: у превышения
  рычаг свой, `waf_exception <фаза> body` сюда не приходит;
* `pass` — не кладётся, инспектор получает `unavailable: oversize`;
* `trim` — кладётся префикс в `<размер>` байт, `truncated: true`, хеш по телу целиком.

Тело, нужное только превью, при превышении не кладётся вовсе: бюджет превью и так не больше
`body_limit`, и срез возьмётся из самого запроса.

`waf_body_max_holds <n>` — умолчание `1000`, на воркер. Это ограничитель не размера одного тела, а
суммарного объёма в полёте: без него медленный инспектор превращает всплеск загрузок в исчерпание
памяти обменника. Достигнутый потолок — `unavailable: store_error` и `WARN` в лог; запрос при этом
не ждёт.

`max=` драйвера — третий потолок, и он проверяется уже в драйвере: объект больше него не пишется, в
логе остаётся `ERR`.

`waf_body_limit` служит заодно потолком любому явному размеру в `waf_capture` и `waf_archive` —
и у тела, и у заголовков, и у строки запроса; на фазе запроса, если `client_max_body_size` меньше,
берётся он. Размер выше этого потолка `nginx -t` не принимает: столько байт модуль не прочитает
вовсе, и настройка была бы обещанием, которого не выполнить.

## Пример: маршрут, который пишет все три объекта

```nginx
http {
    waf_node_id       edge-1;
    waf_agent_socket /run/waf/agent.sock;
    waf_store driver=redis url=redis://redis:6379 ttl=30s retain_ttl=5m max=8m;

    waf_inspector modsec subject=waf.req.modsec;

    server {
        waf on;
        waf_inspect request modsec wave=0;

        waf_capture request headers args body=64k;
        waf_capture request headers deny=authorization,cookie;
        waf_capture request args    mask=token;

        waf_archive request body=8k ttl=180d when=deny;
        waf_archive request reload headers=capture args=capture ttl=180d when=deny;
    }
}
```

Что происходит по запросу с телом в 100 КБ:

1. Перед волной 0 — два `SET`: `edge-1:<rid>:req:hdr` с парами заголовков без `authorization` и
   `cookie`, и `edge-1:<rid>:req:arg` со строкой запроса, где значение `token` заменено хешем. Оба
   с `PX 300000`: объекты названы в `waf_archive`, значит срок — `retain_ttl`, а не `ttl`.
2. Затем `SET edge-1:<rid>:req` с первыми 64 КБ тела, `truncated: true`, `sha256` — по всем 100 КБ.
   64 КБ — это размер `capture`, и больше перед волной не кладётся никогда. `waf_body_limit` при
   этом `1m` по умолчанию, тело в него влезло целиком.
3. Инспектор получает три локатора и читает объекты своим клиентом.
4. После закрытия волн — `reload`, но только при отказе: `when=deny` у обеих строк, а впереди фазы
   нет, и на допущенном запросе оригинал никому не нужен. При отказе `edge-1:<rid>:req:hdr` и
   `edge-1:<rid>:req:arg` переписываются оригиналами, уже без `deny=` и `mask=`. Тело в строке
   `reload` не названо — его ключ не трогают.
5. При отказе ключи не удаляются: владельцем становится агент, и он режет тело до `waf_archive
   body=8k` уже при отправке в S3 — в обменнике всё это время лежат 64 КБ. При разрешении все три
   ключа уходят `DEL`, и всей ценой архива на этом запросе были три `SET` снимка.

Стоит запомнить одно следствие: **шире снимка кладёт только `reload`, и кладёт после вердикта.**
Строка `waf_archive request reload body` без размера означает «оригинал целиком»: перед волной
ляжет снимок в 64 КБ, а на отказе — второй `SET` того же ключа со всеми 100 КБ. Инспектору в
локаторе покажут `size` снимка; в Redis к приходу агента будет больше.

## Что проверяется при nginx -t

| Условие | Сообщение по смыслу |
| --- | --- |
| Маршрут кладёт объекты, а `waf_store` нет либо драйвер `none`/`inline` | «this route places …, which needs waf_store with an external driver» |
| `waf_archive` без инспекторов на маршруте | «needs inspectors on the route» |
| Нет `waf_agent_socket` | «waf_agent_socket is required when waf is on» — общая проверка, она срабатывает раньше архивной и оставляет сообщение «the agent is what moves objects to the archive» видимым только на маршруте с `waf off` |
| `waf_archive` объекта, которого нет в `waf_capture`, без `reload` | «is wider than capture; write reload …» |
| `waf_archive … reload <obj>=capture`, а объекта нет в `capture` | «needs that object in waf_capture» |
| `reload` шире снимка вне фазы запроса | «outside the request phase there is nothing to reload from» |
| `waf_body_limit` больше `max_object` драйвера | «exceeds the … object limit of store driver» |
| Размер у `waf_capture` или `waf_archive` больше того, что модуль вообще читает | «exceeds the … bytes this object the WAF reads at all»; потолок — `waf_body_limit` фазы, а на фазе запроса ещё и `client_max_body_size`, и он один на все три объекта |
| `reload` написан как опция объекта | «unknown option "reload"» |
| `allow=`/`mask=` архива или превью на имя из `deny=` снимка без `reload` объекта | «names "…", which waf_capture deny= drops before the store; write … reload …=capture» |
| `retain_ttl` ниже `ttl` | «retain_ttl … is below ttl» |
| Объект вне словаря фазы | «phase "…" has no object "…"» |

## Кто ещё пишет в обменник

Никто из перечисленных ниже под управлением этих директив не находится, и путать их с записью
объектов запроса не следует.

**Инспектор** кладёт своим клиентом подменённое тело — под ключ, производный от
локатора вопроса плюс суффикс `[a-z0-9_-]{1,32}`, и называет его в секции `rewrite` ответа. Суффиксы
`hdr` и `arg` реплай не принимает: ключ тела с таким хвостом — это ключ заголовков или строки запроса
того же запроса, и подъём «подмены» прочитал бы и удалил их раньше, чем придёт агент. Модуль ключ
подмены читает (`GET`) и удаляет, но не создаёт: отданную версию — сразу после чтения, версии
промежуточных волн — при разрешении вердикта. Отдельного разрешения писать подмену нет (`mutate=on`
снят), а откуда отдавать объект получателю — `waf_send`. Что именно ушло получателю,
после удаления ключа знает только запись: sha256 поднятого объекта в секции `rewrite` и, если
маршрут просил `waf_preview … source=sent`, его срез в превью.

**Агент** обменник только читает и чистит: объекты, оставленные ему, он перекладывает в архив и
убивает ключ сразу после публикации.

**Инспекторы со своим состоянием** (корзины капчи и счётчика, роастер калиток) в обменнике не живут:
их ключи лежат во внутреннем Redis контура (`REDIS_INTERNAL_URL`), там же, где блобы поколений
контроллера. К объектам запроса они отношения не имеют и ни одной директивой nginx не настраиваются —
адреса приходят из окружения самих сервисов. Пустой `REDIS_INTERNAL_URL` у процесса значит, что он
пишет своё состояние в `REDIS_URL`, то есть в обменник, — так было до разделения 11.09.2026.
